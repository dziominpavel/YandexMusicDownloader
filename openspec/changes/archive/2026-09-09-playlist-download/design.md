## Context

См. `proposal.md` (Why). Текущее состояние: `resolver.Parse` принимает только `album/{id}/track/{id}`; `downloader.Client.Download/DownloadMP3` качает один трек через `fetchTrack` + `io.Copy` без счетчика (`mp3.go`, `lossless.go`); `ui.App.Download` — блокирующий вызов одного трека; фронт `index.html` делает `appendChild` на каждый `EventsEmit("log")`. Донор Stmol уже решает плейлисты через `GET /playlist/{uuid}` + `TracksList()` и семафор 3 (`source/url.go`, `source/resolve.go`, `ya/client.go:196`).

## Goals / Non-Goals

**Goals:**
- uuid-плейлисты из окна приложения одной кнопкой, 3 воркера, живой прогресс, итог.
- Переиспользовать пайплайн трека как есть (FLAC first, fallback, теги, `temp → rename`).

**Non-Goals:**
- Legacy-плейлисты `users/{u}/playlists/{id}`, альбомы, чарты — не в этом change.
- Настраиваемая конкурентность, отмена пачки, подпапки под плейлист — позже.
- Изменения теговой схемы — нет (`audio-tagging` не трогаем).

## Decisions

- **Парсинг: regex как у Stmol.** `playlists/((?:[a-z]{2}\.)?[0-9a-fA-F-]{36})` + тот же хост-паттерн `(ru|com|kz|by|uz)`, допуск query-хвоста. Хвост после `uuid.Parse` валидируется, полный ID с префиксом уходит в запрос (как `PlaylistUUID` у Stmol). Альтернатива — строгий uuid без префикса: отклонено, реальные шары приходят с `lk.`/`ps.`.
- **Резолв: один `GET {apiBase}/playlist/{uuid}`, треки из ответа.** Ответ уже содержит полные треки (`TracksList()`), поэтому N запросов `TrackInfo` не делаем; маппим в локальный `Track` один раз. Альтернатива — резолв ID + `TrackInfo` на каждый: отклонено, медленно и лишняя нагрузка. Риск пагинации больших плейлистов (`Pager` в модели) проверяем на плейлисте 100+ при реализации.
- **Пул: семафор с настраиваемым числом воркеров (`PLAYLIST_WORKERS`, дефолт 3, потолок 10), порядок строк не гарантируется.** Воркер = существующий `Download(track)` без изменений пайплайна. `direct_link` получается just-in-time внутри воркера (TTL ~60с уже соблюдается). Эмит событий — через мьютекс/канал, каждая строка атомарна. Число читается из `.env` один раз при старте и кладется в `Client`. Потолок 10 ограничивает давление на API; мусор в настройке → дефолт 3. Альтернатива фиксированных 3: отклонено, пользователь хочет экспериментировать со скоростью.
- **Дедуп и skip до сети.** Дедуп по ID в памяти перед запуском воркеров; проверка `destPath` существует — внутри воркера как сейчас (`ErrAlreadyExists` → `[skip]`). Недоступные (`available=false`) не запускаются вовсе → `[skip] (unavailable)`.
- **Прогресс: новое событие `Progress{TrackID, Label, Done, Total, Percent}`, отдельный канал `progress`.** Счетчик — обертка над `io.Reader` в `downloadToTemp` и `streamLosslessTemp` (обе точки `io.Copy`), троттлинг ~200мс/+1%. `Total` из `resp.ContentLength`, при `-1` — только байты. Канал `log` не трогаем. Альтернатива — пихать прогресс в `log`: отклонено, фронт утонет в строках.
- **Фронт: ровно одна строка на трек.** Перед стартом воркеров UI шлет каркас `tracks` ([id, label] в порядке плейлиста) — фронт строит N строк со статусом `[queued]`. События несут `TrackID` и уходят в отдельный канал `track-status` (короткий статус + цвет), `progress` обновляет встроенный в строку бар. В `#log` пачки попадают только заголовок и `[finished]`; одиночный трек — как раньше (строки в `#log` + бар в `#prog`). Альтернатива — дописывать все события в лог: отклонено, при 36 треках это ~70 строк с повторами имен.
- **UI: блокирующий `DownloadPlaylist`, кнопка disabled.** Wails `EventsEmit` асинхронен, живые события доходят во время блокирующего await. Неблокирующий вызов с джобами — позже (нужны отмена и очередь).

## Risks / Trade-offs

- [Risk] Приватный/чужой плейлист без прав → 403/404 → Mitigation: понятный `[error] плейлист недоступен`, без стека.
- [Risk] Плейлист 200+ треков, API отдает постранично → Mitigation: при реализации проверить поле `Pager`, при наличии — догружать страницы; в tasks есть явный пункт проверки.
- [Risk] Шторм событий прогресса (3 трека x FLAC) → Mitigation: троттлинг + обновление на месте во фронте.
- [Risk] Перемешанный лог при параллельности → принято как trade-off; строки атомарны, итог сводит баланс.
- [Risk] Коллизии имен в плоской раскладке (два разных трека → один `Artist - Title.ext`) → Mitigation: поведение как сейчас (второй пропускается/существует); подпапки — вне скоупа.
