# 15. Мониторинг качества FLAC

Приложение умеет следить за уже скачанными MP3 и предлагать обновить их,
если на Яндекс Музыке появился lossless-вариант. Это не отдельная служба:
проверка работает только пока открыто окно приложения.

## Включение

В `.env` рядом с exe:

```dotenv
FLAC_MONITOR=true
```

По умолчанию параметр выключен. Его же можно включить чекбоксом
«Проверять наличие FLAC автоматически» в окне «Настройки». Изменение
применяется без перезапуска.

## Что проверяется

- Только `.mp3` из `LIBRARY_DIR` (папка коллекции) и `OUTPUT_DIR`
  (папка загрузок), включая подкаталоги.
- Файлы `.flac` уже lossless и пропускаются; `.m4a` в v1 не проверяется.
- Сначала используется Yandex ID из тегов (`YANDEX_TRACK_ID`, UFID или
  source-url). Если ID нет, приложение ищет трек по исполнителю и
  названию через поиск Яндекса и показывает найденного кандидата с
  альбомом, годом и процентом совпадения. Поисковое совпадение скачивается
  только после подтверждения.

## Когда проверяется

- При запуске, если с последней успешной проверки прошло не меньше
  7 дней, и затем раз в 7 дней, пока окно открыто.
- Всегда доступна кнопка «Проверить сейчас» — в главном окне и в
  настройках.
- При закрытом приложении проверок нет; при следующем запуске
  расписание догоняется.

## Что видно

Рядом с кнопкой `FLAC` в главном окне — компактная строка:

```
FLAC: 03.11.2026 18:00 — найдено 67
FLAC: 03.11.2026 18:00 — ничего не найдено
FLAC: 03.11.2026 18:00 — ошибка
FLAC: проверок не было
```

Она обновляется после каждой автопроверки, даже если ничего не найдено.
В настройках те же данные показаны подробнее. При находке открывается
окно со сводкой и списком: локальный файл, `MP3 → FLAC`, для поисковых
совпадений — найденный трек, альбом, год и процент. Кнопки: «Скачать все»,
«Показать список», «Позже». «Позже» сохраняет список и бейдж.

## Что происходит при обновлении

1. Lossless скачивается во временный файл.
2. Если сервер отдал `flac-mp4` (ALAC), при наличии `ffmpeg.exe` и
   `CONVERT_M4A=true` аудио перегоняется в plain FLAC; иначе сохраняется
   lossless `.m4a`.
3. Файл получает теги и публикуется атомарно рядом со старым MP3.
4. Только после успешной публикации старый MP3 перемещается в
   `<корень>\_old\<относительный путь>`.
5. Если вместо lossless пришёл MP3-fallback или публикация не удалась,
   старый файл остаётся на месте.

`_old` игнорируется индексом коллекции и проверкой дублей. Если имя в
`_old` занято, добавляется метка времени. Чистка `_old` — вручную.

## Ограничения

- Нет проверок при закрытом приложении: это десктопное приложение, а не
  служба.
- Нет автоматического скачивания без подтверждения: найденное всегда
  показывается пользователю.
- Без активной подписки Плюс lossless недоступен; проверка сообщает об
  этом и не помечает треки как «FLAC нет».
- Если токен истёк или Яндекс отвечает `smart_preview`, проверка
  останавливается, а журнал не портится. Одиночный 403 по треку означает,
  что трек недоступен; серия из трёх 403 подряд останавливает проверку.
- Файлы без Yandex ID и без пригодных исполнителя/названия пропускаются.
- Уже существующие FLAC не перепроверяются на целостность.

## Журнал

Рядом с `library-index.json` лежит `flac-quality.json`. Он хранит статусы
проверок, время последней попытки/успеха и результат, чтобы не дёргать API
каждый запуск. «FLAC нет» перепроверяется не чаще раза в 30 дней, ошибки —
по короткому TTL, недоступные треки — по длинному. При смене аккаунта или
появлении Плюса журнал сбрасывается. Файл можно удалить — он создастся
заново.
