# Spec Delta

## MODIFIED Requirements

### Requirement: Журнал проверок

Приложение MUST хранить журнал рядом с exe: track ID, кодек, статус, время проверки и срок следующей. «FLAC нет» MUST перепроверяться не чаще раза в 30 дней, ошибки — по короткому TTL, недоступные — по длинному. При смене `accountUID` или переходе `hasPlus` с false на true журнал MUST сбрасываться. Отклонённые поисковые совпадения MUST храниться для локального файла списком вместе с метаданными найденного трека, MUST NOT истекать автоматически и MUST NOT предлагаться снова до явной отмены. При обновлении схемы журнала ранее сохранённые отклонения MUST сохраняться.

#### Scenario: Повторный запуск в пределах TTL

- **WHEN** трек уже проверен и срок следующей проверки не наступил
- **THEN** приложение не делает повторный запрос и не показывает трек

#### Scenario: Сменился аккаунт

- **WHEN** `accountUID` в журнале отличается от текущего
- **THEN** журнал сбрасывается и все кандидаты проверяются заново

#### Scenario: Появился Плюс

- **WHEN** у того же аккаунта `hasPlus` изменился с false на true
- **THEN** записи «FLAC нет» сбрасываются и треки проверяются заново

#### Scenario: Поисковое совпадение отклонено

- **WHEN** пользователь нажал «Не тот трек» у поискового совпадения
- **THEN** это совпадение запоминается и не предлагается снова до явного возврата

#### Scenario: Отклонение переживает перезапуск

- **WHEN** приложение перезапущено после отклонения поискового совпадения
- **THEN** сохранённые отклонения остаются активными и не предлагаются снова

#### Scenario: Отклонение не истекает

- **WHEN** после отклонения прошло больше 180 дней
- **THEN** отклонённое совпадение всё ещё не предлагается, пока пользователь не вернёт его

#### Scenario: Старый журнал мигрирует

- **WHEN** приложение загружает журнал версии 1 с непустым `declined`
- **THEN** сохранённые отклонения переносятся в журнал версии 2 и остаются активными

### Requirement: Окно найденного

При находке приложение MUST сохранить список и показать бейдж количества на кнопке «Настройки»; окно MUST открываться из настроек. Окно MUST показывать локальный файл, текущий и найденный форматы и папку назначения нового FLAC (`OUTPUT_DIR`); для поисковых совпадений — найденный трек, альбом, год и процент. ID-совпадения MUST быть предвыбраны, поисковые — только при уверенном совпадении. Для каждого поискового совпадения MUST быть действие «Не тот трек», которое убирает строку из текущего списка и сохраняет отклонение без скачивания; для ID-совпадений это действие MUST NOT показываться. После отклонения сводка и бейдж MUST обновляться, а если строк не осталось — окно MUST закрываться. Действия: «Скачать все», «Показать список», «Позже». «Позже» MUST сохранять список и бейдж; при отсутствии находок окно MUST NOT показываться.

#### Scenario: Много ID-совпадений

- **WHEN** проверка нашла 67 треков по ID
- **THEN** окно показывает сводку «Найдено 67 треков», все предвыбраны, доступны «Скачать все» и «Показать список»

#### Scenario: Поисковые совпадения

- **WHEN** найдены треки без ID
- **THEN** они показаны отдельно с найденным треком, альбомом, годом и процентом; предвыбраны только уверенные совпадения

#### Scenario: Ничего не найдено

- **WHEN** проверка не нашла ни одного lossless-варианта
- **THEN** окно не показывается, в логе остаётся итоговая строка проверки

#### Scenario: Позже

- **WHEN** пользователь нажал «Позже»
- **THEN** окно закрывается, найденное сохраняется, а на кнопке «Настройки» остаётся бейдж с количеством

#### Scenario: Открытие из настроек

- **WHEN** есть найденные треки, пользователь открыл настройки и нажал «Открыть найденное»
- **THEN** открывается окно со сводкой и списком

#### Scenario: Папка назначения видна

- **WHEN** в списке есть MP3 из папки коллекции
- **THEN** окно показывает, что новый FLAC будет скачан в `OUTPUT_DIR`, а старый MP3 перемещён в `_old`

#### Scenario: Отклонение в окне

- **WHEN** пользователь нажал «Не тот трек» у поискового совпадения
- **THEN** строка исчезает из списка, файл не скачивается, отклонение сохраняется, а бейдж уменьшается на единицу

#### Scenario: Последнее совпадение отклонено

- **WHEN** пользователь отклонил единственное оставшееся поисковое совпадение
- **THEN** окно закрывается, а бейдж скрывается

#### Scenario: ID-совпадение не отклоняется

- **WHEN** найденный элемент получен по Yandex ID
- **THEN** действие «Не тот трек» для него не показывается

### Requirement: Логи

Проверка, обновление, отклонение и возврат MUST писать в лог понятные строки на русском: начало и итог проверки, найденные треки, обновление, причину отказа или ошибки, отклонённый и возвращённый кандидат. При отсутствии находок MUST быть только итоговая строка. Токен и `Authorization` MUST NOT попадать в лог.

#### Scenario: Найдены треки

- **WHEN** проверка нашла lossless-варианты
- **THEN** в логе есть итог проверки и строки о найденных/обновлённых треках

#### Scenario: Ничего не найдено

- **WHEN** проверка не нашла ни одного варианта
- **THEN** в логе есть только итоговая строка проверки

#### Scenario: Ошибка проверки

- **WHEN** проверка остановлена из-за токена, прав или сети
- **THEN** в логе есть понятная причина на русском, а токен не раскрыт

#### Scenario: Отклонение в логе

- **WHEN** пользователь отклонил поисковое совпадение
- **THEN** в логе есть локальный файл и найденный трек, а токен не раскрыт

#### Scenario: Возврат в логе

- **WHEN** пользователь вернул отклонённое совпадение
- **THEN** в логе есть локальный файл и найденный трек, а токен не раскрыт

## ADDED Requirements

### Requirement: Явное отклонение поискового совпадения

Пользователь MUST иметь возможность отклонить поисковое совпадение в окне найденного, не скачивая его. Отклонение MUST сохраняться для локального файла и идентификатора найденного трека. Несколько отклонений одного файла MUST храниться независимо и MUST NOT затирать друг друга. Отклонённый кандидат MUST NOT предлагаться для этого файла до явной отмены. Отклонение MUST NOT менять, перемещать или удалять аудиофайл.

#### Scenario: Кандидат отклонён

- **WHEN** пользователь нажал «Не тот трек» у поискового совпадения
- **THEN** кандидат исчезает из списка, аудиофайл остаётся на месте, а отклонение сохраняется

#### Scenario: Второй кандидат отклонён

- **WHEN** пользователь отклонил второго кандидата для того же локального файла
- **THEN** оба отклонения сохранены, и ни один из отклонённых кандидатов не предлагается

### Requirement: Проверка после отклонения

После отклонения локальный MP3 MUST оставаться кандидатом мониторинга. Приложение MUST сбросить результат проверки, из-за которого файл считался lossless, и при следующей проверке MUST искать другие совпадения, исключая отклонённые. Если все найденные кандидаты отклонены, следующая проверка файла MUST быть назначена не позднее чем через 7 дней.

#### Scenario: Другая версия

- **WHEN** после отклонения запускается следующая проверка
- **THEN** файл снова проверяется, отклонённый кандидат исключается, а другое совпадение может быть предложено

#### Scenario: Все кандидаты отклонены

- **WHEN** для файла отклонены все найденные кандидаты
- **THEN** следующая проверка файла назначается не позднее чем через 7 дней

### Requirement: Возврат отклонённого совпадения

Пользователь MUST иметь возможность отменить отклонение. Возврат MUST удалять запись об отклонении и снова делать кандидата доступным для предложения без автоматического скачивания. Если сохранённые метаданные позволяют, кандидат MUST снова появляться в списке найденного сразу; иначе — при следующей проверке. Возврат MUST обновлять бейдж и список найденного.

#### Scenario: Возврат из настроек

- **WHEN** пользователь нажал «Вернуть» у отклонённого совпадения
- **THEN** запись об отклонении удаляется, кандидат снова доступен для предложения, а скачивание не запускается

#### Scenario: Кандидат сразу в списке

- **WHEN** для отклонённого совпадения сохранены метаданные найденного трека
- **THEN** после возврата кандидат сразу появляется в списке найденного и в бейдже

#### Scenario: Повторный отказ

- **WHEN** пользователь снова отклонил возвращённое совпадение
- **THEN** оно опять скрывается и не предлагается до следующего возврата
