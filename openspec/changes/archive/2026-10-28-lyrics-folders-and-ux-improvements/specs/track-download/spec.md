# Spec Delta

## MODIFIED Requirements

### Requirement: Скачивание трека по ссылке

Приложение MUST принимать ссылку вида `music.yandex.ru/album/{albumId}/track/{trackId}`, ссылку вида `music.yandex.(ru|com|kz|by|uz)/album/{albumId}` (без trackId), ссылку вида `music.yandex.(ru|com|kz|by|uz)/playlists/{uuid}` (включая префиксы вида `lk.<uuid>`, `ps.<uuid>` и query-хвосты), а также несколько ссылок в одном вводе (разделённые переносом строки, пробелом или запятой). Приложение MUST скачивать аудио в `OUTPUT_DIR` (по умолчанию `./downloads`).

#### Scenario: Вставил ссылку — получил файл

- **WHEN** пользователь вставляет ссылку на трек и нажимает «Скачать»
- **THEN** в логе появляется `[downloading] Artist — Title`, а после завершения — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Файл уже есть

- **WHEN** целевой файл уже существует в папке назначения
- **THEN** скачивание пропускается и в логе появляется `[skip] Artist — Title (already exists)`

#### Scenario: Вставил ссылку на плейлист — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.by/playlists/{uuid}` и нажимает «Скачать»
- **THEN** появляется заголовок `[playlist] Название (N треков)` и ровно по одной строке на каждый уникальный трек (в порядке плейлиста, со статусом `[queued]`), а в конце — `[finished] X ok, Y skip, Z error`

#### Scenario: Вставил ссылку на альбом — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.ru/album/{albumId}` и нажимает «Скачать»
- **THEN** приложение резолвит альбом в список треков и скачивает их тем же способом, что и плейлист: заголовок `[album] Название (N треков)`, по одной строке на каждый трек, общий прогресс, итоговая строка `[finished] X ok, Y skip, Z error`

#### Scenario: Одна строка на трек

- **WHEN** трек плейлиста или альбома качается и завершается
- **THEN** его строка обновляется на месте (`[queued]` → `[downloading]` → `[done] (FLAC|MP3)` с цветом), новые строки на каждое событие НЕ добавляются; строка пропуска показывает `[skip] (already exists|duplicate|unavailable)`, строка ошибки — `[error]` с причиной

#### Scenario: Плейлист с query-хвостом и префиксом

- **WHEN** ссылка имеет вид `music.yandex.ru/playlists/lk.<uuid>?utm_source=web`
- **THEN** приложение принимает ее как плейлист и резолвит тот же набор треков, что и без префикса и хвоста

#### Scenario: Несколько ссылок разом

- **WHEN** пользователь вставляет в поле ввода несколько ссылок (разделённые переносом строки, пробелом или запятой), нажимает «Скачать»
- **THEN** приложение обрабатывает каждую ссылку по очереди, применяя соответствующий пайплайн для каждого (альбом/плейлист/трек). Если одна из ссылок некорректна — она пропускается с `[error]`, остальные обрабатываются дальше.

## ADDED Requirements

### Requirement: Подпапки при скачивании

Приложение MUST иметь настройки `SUBDIRS` (по умолчанию `false`) и `SUBDIR_TEMPLATE` (по умолчанию `%artist%/%album%`). Если `SUBDIRS=true`, приложение MUST создавать подпапки по шаблону относительно `OUTPUT_DIR`. Шаблон MUST поддерживать подстановки `%artist%`, `%album%`, `%year%`. Имена директорий MUST подчиняться правилу сортировки кириллицы и санитизации из `docs/12-file-naming.md`. Если `SUBDIRS=false`, файлы MUST сохраняться прямо в `OUTPUT_DIR` как раньше.

#### Scenario: Подпапки выключены по умолчанию

- **WHEN** `SUBDIRS` не задан или `false`
- **THEN** файлы сохраняются плоско в `OUTPUT_DIR`

#### Scenario: Подпапки по альбому включены

- **WHEN** `SUBDIRS=true`, шаблон по умолчанию `%artist%/%album%`
- **THEN** файл сохраняется в `OUTPUT_DIR/<исполнитель>/<альбом>/Имя файла`

### Requirement: Экспорт плейлиста/альбома в m3u

Приложение MUST иметь настройку `EXPORT_M3U` (по умолчанию `false`). Если `EXPORT_M3U=true` и скачивается альбом или плейлист, приложение MUST создать `.m3u` файл рядом с файлами (в той же директории, что и треки этого скачивания) с путями к скачанным трекам. Файл создаётся без ошибки, если экспорт не удался.

#### Scenario: Экспорт включён

- **WHEN** скачивается плейлист и `EXPORT_M3U=true`
- **THEN** в папке с треками появляется `.m3u` файл со списком

#### Scenario: Экспорт выключен по умолчанию

- **WHEN** `EXPORT_M3U` не задан или `false`
- **THEN** `.m3u` файл не создаётся

### Requirement: UX улучшения без настроек

Приложение MUST поддерживать drag & drop ссылок на окно, кнопку «Открыть папку загрузок», историю последних ссылок (хранить в localStorage, максимум 15-20) и предпросмотр ссылки (обложка, название, артист, кол-во треков для альбома/плейлиста). Предпросмотр MUST НЕ блокировать нажатие «Скачать»; при ошибке предпросмотра он MUST скрываться без ошибки. Все эти функции MUST быть включены всегда, без опций в окне настроек.

#### Scenario: Drag & drop

- **WHEN** пользователь перетаскивает ссылку Яндекс.Музыки на окно
- **THEN** ссылка подставляется в поле ввода и можно сразу скачать

#### Scenario: Открыть папку загрузок

- **WHEN** пользователь нажимает «Открыть папку загрузок»
- **THEN** системный проводник открывается на папке `OUTPUT_DIR`

#### Scenario: История ссылок

- **WHEN** пользователь скачал ссылку
- **THEN** она появляется в выпадающем списке истории (максимум 15-20), при клике подставляется в поле

#### Scenario: Предпросмотр ссылки

- **WHEN** в поле ввода вставлена валидная ссылка на трек/альбом/плейлист
- **THEN** показывается компактный предпросмотр (обложка, название, артист/кол-во треков). Нажатие «Скачать» работает независимо от предпросмотра; если превью не загрузилось — блок предпросмотра скрывается
