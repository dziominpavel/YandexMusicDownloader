## Why

Сейчас приложение качает только один трек за раз. Пользователь хочет вставить ссылку вида `https://music.yandex.by/playlists/{uuid}` и получить все треки плейлиста сразу, с живым прогрессом по каждому треку в окне приложения.

## What Changes

- Прием ссылки на плейлист вида `music.yandex.(ru|com|kz|by|uz)/playlists/{uuid}` (включая префиксы вида `lk.<uuid>`, `ps.<uuid>` и query-хвосты `?utm_source=...`).
- Резолв плейлиста в список треков через `GET /playlist/{uuid}`: один запрос, дедуп по ID, недоступные треки помечаются для пропуска.
- Пакетное скачивание пулом воркеров с настраиваемым числом (**`PLAYLIST_WORKERS`** в `.env`, по умолчанию 3, максимум 10): каждый трек качается по текущему пайплайну (lossless first, MP3 fallback, теги, `temp → rename`).
- Живой прогресс по каждому треку в окне приложения (байты/проценты, обновление строки на месте, троттлинг).
- Ошибка одного трека не останавливает плейлист; в конце итоговая строка `[finished] X ok, Y skip, Z error`.
- Раскладка остается плоской (`Artist - Title.ext` прямо в `downloads/`), без подпапок под плейлист.

## Capabilities

### New Capabilities

- Нет новых capability: плейлист — расширение существующей подсистемы скачивания.

### Modified Capabilities

- `track-download`: прием плейлист-ссылки, пакетное скачивание настраиваемым пулом воркеров, прогресс по трекам, skip-политика для недоступных/дублей, итоговая строка.

## Impact

- `src/internal/resolver/` — парсинг uuid-ссылки, резолв через `/playlist/{uuid}`.
- `src/internal/downloader/` — worker pool на 3, событие прогресса, счетчик байт в обеих качалках (MP3 и lossless), дедуп и сбор итога.
- `src/internal/ui/` — новый метод пакетного скачивания (блокирующий, кнопка disabled), проброс прогресса во фронт.
- `src/frontend/dist/index.html` — строки прогресса с ключом по треку + итог; канал `log` сохраняется для терминальных строк.
- Спеки: delta к `track-download`; `audio-tagging` не меняется (теги как для одиночного трека).
