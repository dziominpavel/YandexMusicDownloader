## MODIFIED Requirements

### Requirement: Скачивание трека по ссылке

Приложение MUST принимать ссылку вида `music.yandex.ru/album/{albumId}/track/{trackId}` и ссылку вида `music.yandex.(ru|com|kz|by|uz)/playlists/{uuid}` (включая префиксы вида `lk.<uuid>`, `ps.<uuid>` и query-хвосты) и скачивать аудио в `OUTPUT_DIR` (по умолчанию `./downloads`).

#### Scenario: Вставил ссылку — получил файл

- **WHEN** пользователь вставляет ссылку на трек и нажимает «Скачать»
- **THEN** в логе появляется `[downloading] Artist — Title`, а после завершения — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Файл уже есть

- **WHEN** целевой файл уже существует в папке назначения
- **THEN** скачивание пропускается и в логе появляется `[skip] Artist — Title (already exists)`

#### Scenario: Вставил ссылку на плейлист — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.by/playlists/{uuid}` и нажимает «Скачать»
- **THEN** появляется заголовок `[playlist] Название (N треков)` и ровно по одной строке на каждый уникальный трек (в порядке плейлиста, со статусом `[queued]`), а в конце — `[finished] X ok, Y skip, Z error`

#### Scenario: Одна строка на трек

- **WHEN** трек плейлиста качается и завершается
- **THEN** его строка обновляется на месте (`[queued]` → `[downloading]` → `[done] (FLAC|MP3)` с цветом), новые строки на каждое событие НЕ добавляются; строка пропуска показывает `[skip] (already exists|duplicate|unavailable)`, строка ошибки — `[error]` с причиной

#### Scenario: Плейлист с query-хвостом и префиксом

- **WHEN** ссылка имеет вид `music.yandex.ru/playlists/lk.<uuid>?utm_source=web`
- **THEN** приложение принимает ее как плейлист и резолвит тот же набор треков, что и без префикса и хвоста

## ADDED Requirements

### Requirement: Пакетное скачивание плейлиста

Приложение MUST скачивать треки плейлиста пулом параллельных воркеров с настраиваемым числом (`PLAYLIST_WORKERS` в `.env`: целое 1..10, по умолчанию 3), при этом каждый трек MUST проходить стандартный пайплайн (FLAC first с MP3-fallback, обязательные теги, потоковая запись, атомарная публикация `temp → rename`). Ошибка или недоступность одного трека MUST NOT останавливать остальные. Повтор одного и того же ID внутри плейлиста MUST скачиваться один раз, повторные вхождения пропускаются как уже обработанные.

#### Scenario: Пачка из нескольких треков

- **WHEN** плейлист содержит 5 уникальных доступных треков
- **THEN** все 5 файлов появляются в `downloads/` с тегами, 5 строк треков переходят в `[done]`, а финал — `[finished] 5 ok, 0 skip, 0 error`

#### Scenario: Недоступный трек пропускается

- **WHEN** трек плейлиста недоступен (`available=false`, нет прав, 403/404)
- **THEN** строка трека показывает `[skip] (unavailable)`, остальные треки качаются дальше, счетчик `skip` в финале увеличивается

#### Scenario: Дубль качается один раз

- **WHEN** один и тот же ID встречается в плейлисте дважды
- **THEN** файл скачивается один раз, строка трека показывает `[skip] (duplicate)`, повторной записи файла нет

#### Scenario: Ошибка одного не роняет пачку

- **WHEN** один трек завершается ошибкой сети или тегирования
- **THEN** строка трека показывает `[error]` с причиной, остальные треки продолжают качаться, финал учитывает ошибку в счетчике `error`

#### Scenario: Число воркеров настраивается

- **WHEN** в `.env` задано `PLAYLIST_WORKERS=10`
- **THEN** до 10 треков качаются параллельно

#### Scenario: Мусор в настройке воркеров

- **WHEN** `PLAYLIST_WORKERS` отсутствует, не число или вне диапазона 1..10
- **THEN** приложение использует значение по умолчанию 3 и работает как обычно

### Requirement: Прогресс скачивания трека

Приложение MUST показывать живой прогресс по каждому качающемуся треку плейлиста (байты и проценты при известном размере, только байты при неизвестном), обновляя строку трека на месте, а не добавляя новые строки. Обновления MUST быть троттлированы (не чаще ~200 мс или +1% на трек), чтобы не затапливать UI. Статусы треков MUST обновляться в их строках; в обычный лог попадают только заголовок плейлиста и итоговая строка `[finished]`.

#### Scenario: Виден процент по треку

- **WHEN** качаются 3 трека параллельно с известным размером
- **THEN** в окне видны 3 обновляющиеся строки вида `Artist — Title 42% 18/43 МБ`, каждая обновляется независимо

#### Scenario: Неизвестный размер

- **WHEN** сервер не отдал размер файла
- **THEN** строка прогресса показывает только скачанные байты вида `Artist — Title 12 МБ`, без процентов, и трек завершается обычным `[done]`
