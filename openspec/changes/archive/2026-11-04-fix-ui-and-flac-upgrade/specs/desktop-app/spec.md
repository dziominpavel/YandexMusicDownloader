# Spec Delta

## ADDED Requirements

### Requirement: Бейдж найденных FLAC на кнопке настроек

Кнопка «Настройки» MUST показывать бейдж с количеством найденных обновлений FLAC, пока список не пуст. Автопроверка и завершённое обновление MUST обновлять бейдж без перезапуска. Бейдж MUST исчезать, когда список пуст. Доступное имя кнопки MUST включать количество найденного. Автопроверка MUST NOT открывать окно найденного сама.

#### Scenario: Автопроверка нашла треки

- **WHEN** автопроверка завершилась и нашла 3 трека
- **THEN** на кнопке «Настройки» появляется бейдж «3», а окно найденного само не открывается

#### Scenario: Обновление завершилось

- **WHEN** все найденные треки обновлены
- **THEN** бейдж на кнопке «Настройки» исчезает без перезапуска

#### Scenario: Позже

- **WHEN** пользователь закрыл окно найденного кнопкой «Позже»
- **THEN** бейдж остаётся, а открыть список можно из настроек

#### Scenario: Ничего не найдено

- **WHEN** проверка завершилась без находок
- **THEN** бейдж на кнопке «Настройки» не появляется

#### Scenario: Доступное имя с количеством

- **WHEN** найдено 3 трека и пользователь фокусирует кнопку «Настройки» скринридером
- **THEN** доступное имя кнопки содержит количество найденного

## MODIFIED Requirements

### Requirement: Окно с полем, кнопкой и логом

Приложение MUST открываться как обычное Windows-окно с полем для ссылки, кнопкой «Скачать», кнопкой «Настройки», агрегированным прогрессом (см. capability `track-download`) и строковым логом. Все тексты интерфейса — на русском. Главное действие MUST быть визуально доминирующим. Лог MUST быть доступен в сворачиваемой панели «Подробности» и MUST NOT занимать основной экран по умолчанию. Ошибки MUST показываться рядом с полем ввода и дублироваться в логе.

#### Scenario: Скачивание из окна

- **WHEN** пользователь вставляет ссылку на трек в поле и нажимает «Скачать»
- **THEN** в логе появляется `[downloading] Artist — Title`, а по завершении — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Ошибка видна в окне

- **WHEN** скачивание завершается ошибкой (нет сети, неверная ссылка, недоступный трек)
- **THEN** рядом с полем ввода появляется ошибка с краткой причиной на русском и действием «Повторить», подробности доступны в панели «Подробности», окно остаётся открытым

#### Scenario: Настройки открыты из окна

- **WHEN** пользователь нажимает «Настройки»
- **THEN** открывается окно настроек (см. capability `app-settings`), главный экран при этом остаётся позади

#### Scenario: Лог свёрнут по умолчанию

- **WHEN** приложение запущено и загрузок ещё не было
- **THEN** панель «Подробности» свёрнута и не занимает основной экран, но доступна по нажатию

#### Scenario: Главное действие на старте

- **WHEN** пользователь открыл приложение и не начал загрузку
- **THEN** кнопка «Скачать» визуально доминирует, а настройки и папка оформлены как второстепенные действия

### Requirement: Визуальная иерархия и состояния контролов

Интерфейс MUST использовать единую визуальную систему: один акцентный цвет для главного действия, семантические цвета для успеха, предупреждения и ошибки, а также различимые состояния hover, focus-visible, active и disabled. Эмодзи MUST NOT использоваться как иконки управления; иконки MUST быть векторными. Моноширинный шрифт MUST использоваться только для лога и технических значений.

#### Scenario: Единственный акцент

- **WHEN** пользователь находится на экране ожидания без контекстного баннера
- **THEN** акцентную заливку имеет только кнопка «Скачать», а остальные действия визуально второстепенны

#### Scenario: Клавиатурный фокус

- **WHEN** пользователь перемещается по интерфейсу клавишей Tab
- **THEN** каждый интерактивный элемент показывает заметное focus-состояние, не полагаясь только на цвет текста

#### Scenario: Недоступное действие

- **WHEN** действие недоступно, например «Настройки» во время загрузки
- **THEN** оно выглядит отключённым и не меняет курсор на «ожидание», если действие не выполняется

#### Scenario: Иконки без эмодзи

- **WHEN** пользователь смотрит на панель действий
- **THEN** папка и настройки показаны векторными иконками, а не эмодзи

#### Scenario: Технический текст отделён

- **WHEN** пользователь смотрит на список треков и статусы
- **THEN** они набраны интерфейсным шрифтом, а моноширинный шрифт виден только в логе и технических значениях

## REMOVED Requirements

### Requirement: Кнопка проверки FLAC и бейдж

**Reason**: Кнопка дублировала проверку, которая теперь запускается из раздела «Мониторинг FLAC» в настройках; бейдж найденного переехал на кнопку «Настройки».

**Migration**: Запускать проверку кнопкой «Проверить сейчас» в настройках; количество найденного показывается бейджем на кнопке «Настройки», список открывается из настроек.

### Requirement: Индикация последней проверки в главном окне

**Reason**: Главное окно больше не показывает состояние FLAC-монитора; статус последней проверки остаётся в настройках.

**Migration**: Смотреть дату, время и результат последней проверки в разделе «Мониторинг FLAC» окна настроек.
