# 14. Ревью проекта и предложения по улучшению

*Дата: 2026-10-27 | Роль: архитектор + бизнес-аналитик + дизайнер*

## Краткое резюме

Проект хорошо продуман. Основная задача (скачивание из Яндекс.Музыки в FLAC с тегами) реализована и работает. MVP зрелый, с хорошей проработкой спецификаций (OpenSpec), архитектуры и UX-деталей. 

Ключевые сильные стороны:
- **Спецификации** — отличная работа с OpenSpec (track-download, audio-tagging). Требования конкретны и проверяемы.
- **Архитектура** — модульная (config/resolver/downloader/tagger/library/ui), понятная, хорошо задокументирована.
- **UX** — минималистичный, фокус на главном сценарии. Много тонких правок (статусбар, стоп, дубли по коллекции).
- **Надёжность** — потоковая запись, атомарность, параллельная загрузка плейлиста, обработка ошибок.
- **Теги** — приоритет на корректные теги, мультиартисты, обложка, правило именования для кириллицы.

Основные зоны для улучшения: расширение функциональности для повседневного использования, доработка дизайна UI, улучшение навигации/организации файлов, производительность индексации, обработка больших плейлистов.

## 1. Архитектура

### Сильные стороны
- Чёткое разделение ответственности, интерфейсы через события (`Event`, `Progress`)
- Инъекции зависимостей в тестах (downloadOne, downloadBatch, confirm)
- Конфиг через `.env` с сохранением комментариев (`config.Write`)
- Горячее применение настроек без перезапуска

### Предложения

| Предложение | Приоритет | Описание | Усложнение |
|---|---|---|---|
| **Единая очередь загрузок** | Высокий | Сейчас можно запустить новую загрузку, пока старая идёт? UI блокирует настройки, но кнопка "Стоп" есть. Лучше явно показывать очередь: можно добавлять ссылки в очередь, пауза/возобновление. | Средне-высокое |
| **State machine для job** | Средний | Явный стейт-машина вместо флагов `busy`, `stopped`. Проще тестировать, меньше гонок. | Среднее |
| **Кэш резолва** | Средний | Кэшировать резолв треков/альбомов на время сессии (особенно при повторных попытках). Снизит нагрузку на API. | Низкое |
| **Structured logging** | Низкий | Вместо текстовых строк лога — структурированные события с уровнями. Упростит отладку, возможность фильтрации. | Среднее |
| **Модульные ошибки** | Низкий | Кастомные типы ошибок с кодами для лучшей обработки в UI. | Низкое |

### Дизайн-концепт

Простая, чистая концепция в духе современных десктоп-приложений:

```
┌─────────────────────────────────────────────────────────┐
│  YandexMusicDownloader                    [⚙] [─][□][×] │
├─────────────────────────────────────────────────────────┤
│  [Вставь ссылку или перетащи сюда]        [Скачать]     │
│  ████████████░░░░  12/24 треков • 245/512 МБ           │
├─────────────────────────────────────────────────────────┤
│  ТРЕКИ В ЗАГРУЗКЕ                                      │
│  ┌─────────────────────────────────────────────────────┐│
│  │ [обложка] Artist - Title                    [▮▮▮]  ││
│  │           Альбом • FLAC • 42% • 18.2/43.1 МБ       ││
│  └─────────────────────────────────────────────────────┘│
│  [История загрузок ▼]                                   │
└─────────────────────────────────────────────────────────┘
```

Ключевые идеи:
- Обложки в списке треков (64х64) — нагляднее
- Прогресс детальнее с форматом/размером
- Переход от "лога" к "списку" как основной вид
- Меньше технических `[downloading]`, больше человекочитаемого

## 3. Новый полезный функционал

### Критично/очень полезно

| Функция | Приоритет | Описание | Реализация |
|---|---|---|---|
| **Скачивание альбомов** | Критичный | `music.yandex.ru/album/{id}` — очень частый случай. Сейчас только трек и плейлист. | Resolver уже частично поддерживает? Проверить. В спеке есть упоминание v0.2. |
| **Скачивание артистов/исполнителей** | Высокий | Популярные альбомы артиста, дискография. | Требует изучения API. |
| **Скачивание по ID** | Низкий | Прямая вставка ID трека/альбома. | Простое расширение резолвера. |
| **Выбор качества при отсутствии FLAC** | Средний | Сейчас всегда лучший MP3. Иногда хочется сохранить как есть или выбрать 192. | Конфиг опциональный, по умолчанию автопилот. |
| **Сохранение в подпапки по альбому** | Высокий | В спеке есть `docs/12-file-naming.md` про плоскую раскладку, но пользователи часто хотят `Artist/Album/01 - Title.flac`. Сделать опциональным. | Настройка в UI + логика в tagger/namer. |
| **Лирика (lyrics)** | Средний | Скачать `.lrc` файл рядом с треком. Я.Музыка часто имеет тексты. | Новый модуль, опциональный. |
| **Коверы отдельно** | Низкий | Сохранять `cover.jpg` в папку альбома (опция). | Уже частично есть идея в спеке. |

### Полезные дополнения

| Функция | Приоритет | Описание | Реализация |
|---|---|---|---|
| **Поиск по названию** | Средний | Поиск трека/альбома по запросу без ссылки. Удобнее. | Требует API поиска из MarshalX. |
| **Избранное/Мои плейлисты** | Средний | Авторизация позволяет видеть коллекцию пользователя. Список своих плейлистов с выбором для скачивания. | Нужна авторизация через токен (уже есть). |
| **Синхронизация** | Низкий | Сравнить локальную коллекцию с Я.Музыкой, скачать недостающее. | Сложно, но интересно. |
| **Экспорт списка** | Низкий | Сохранить список треков плейлиста в M3U/JSON. | Тривиально. |
| **Batch из ссылок** | Высокий | Вставить сразу несколько ссылок (по одной на строку) — скачать все подряд. | UI + парсер. |

## 4. Улучшение текущего функционала

### Качество и надёжность

| Улучшение | Приоритет | Описание |
|---|---|---|
| **Ретраи** | Критичный | При сетевых ошибках автоматически ретраить (3-5 попыток) с экспоненциальным бэкоффом. Особенно важно для плейлистов. |
| **Таймауты** | Критичный | Настраиваемые таймауты соединения/чтения. Избежать зависаний. |
| **Проверка целостности FLAC** | Высокий | После скачивания быстрая проверка заголовка FLAC. Если битый — ретрай/фолбэк. |
| **Resume (докачка)** | Средний | При обрыве докачивать с места, а не с нуля. Сложнее с шифрованием, но возможно. |
| **Больше источников зеркал** | Средний | Если одно зеркало не работает — попробовать другое (как в некоторых реализациях). |

### Производительность

| Улучшение | Приоритет | Описание |
|---|---|---|
| **Быстрая индексация** | Высокий | Индексация большой коллекции (тысячи треков) может быть медленной. Кэшировать метаданные, параллелить сканирование. |
| **Поиск дублей оптимизация** | Высокий | Использовать нормализацию, fuzzy matching эффективнее. Возможно добавлять в индекс хеши первых KB для быстрого сравнения. |
| **Предзагрузка обложек** | Низкий | Кэш обложек для предпросмотра. |
| **Меньше аллокаций** | Низкий | Профилирование в Go, оптимизация горячих путей. |

### Теги и файлы

| Улучшение | Приоритет | Описание |
|---|---|---|
| **Больше тегов** | Средний | Добавить `COMPOSER`, `COPYRIGHT`, `LABEL`, `ISRC` если есть в API. |
| **Исправление YEAR/DATE** | Низкий | Некоторые треки имеют только год, некоторые полную дату. Единообразие. |
| **Нормализация названий** | Средний | Убрать лишние пробелы, "feat." vs "ft." унификация. |
| **Многодисковые альбомы** | Высокий | Улучшить поддержку (уже есть упоминание в спеке). Сейчас правило именования не учитывает диск. |
| **Треки с версией** | Низкий | `(Remaster)`, `(Deluxe)` и т.п. — часть названия или отдельный тег. |

## 5. Конкретные предложения по реализации

### Быстрые победы (малые изменения, большой эффект)

1. **Drag & Drop** — добавить event listeners в HTML/JS, передавать в Go
2. **История ссылок** — localStorage в браузере + выпадающий список
3. **Горячие клавиши** — простой JS
4. **Альбомы** — проверить resolver, добавить поддержку в UI
5. **Ретраи** — обернуть сетевые вызовы в retry логику

### Средние по сложности

1. **Карточки треков с обложками** — нужно получать обложку URL, кэшировать, отображать
2. **Подпапки по альбому** — настройка + логика формирования пути
3. **Поиск** — UI поиск + интеграция с API
4. **Лирика .lrc** — fetch lyrics API, парсинг, сохранение

### Крупные

1. **Своя библиотека/плейлисты пользователя** — авторизация, получение плейлистов, UI выбора
2. **Синхронизация** — сложная логика сравнения
3. **Resume** — работа с диапазонами байтов + шифрование

## 6. Рекомендации по дизайну

### Цветовая палитра

Текущая тёмная тема хороша. Предлагаю чуть освежить:

```css
:root {
  --bg-primary: #0d1117;
  --bg-secondary: #161b22;
  --bg-tertiary: #21262d;
  --border: #30363d;
  --text-primary: #e6edf3;
  --text-secondary: #8b949e;
  --accent: #58a6ff;
  --success: #3fb950;
  --warning: #d29922;
  --error: #f85149;
  --stopped: #d29922;
}
```

### Компоненты

- **Input** — больше padding, focus state с акцентом
- **Button primary** — градиент или сплошной акцент
- **Button danger** — для стопа (уже есть, улучшить)
- **Cards** — rounded corners 8-12px, subtle border
- **Progress bars** — чуть выше, с анимацией

### Анимации

Мягкие, ненавязчивые:
- `transition: all 150ms ease`
- Fade in для новых строк/карточек
- Pulse для активного скачивания
- Skeleton loading для предпросмотра

## 8. Заключение

Проект в отличном состоянии. Главный совет — не раздувать до "всеобъемлющего" менеджера музыки, сохранить философию "одно поле + кнопка". 

Самые ценные улучшения с точки зрения пользователя:
1. **Альбомы** — закрывает огромный спрос
2. **Подпапки по альбому** — лучше организация коллекции
3. **Drag & Drop + история** — удобство повседневного использования
4. **Ретраи** — надёжность
5. **Карточки с обложками** — приятнее UI

Дизайн можно освежить аккуратно, не ломая текущую простоту. Архитектура позволяет добавлять фичи без больших рефакторингов.

**Итого: 9/10**. Отличная работа. С фокусом на перечисленных улучшениях станет ещё лучше.
