## Why

Два дефекта окна, найденные при ручной проверке настроек:

1. Чекбокс в окне настроек назван двойным отрицанием — «Не встраивать обложку» — и по умолчанию выключен. Пользователь видит снятую галочку у отрицательной формулировки и не понимает с первого взгляда, встроит приложение обложку или нет. Правильнее положительная формулировка с включённой по умолчанию галкой.
2. Окно всегда открывается 720×480: на первом запуске оно маленькое, пользователь каждый раз тянет его руками, а после закрытия старания теряются — при следующем запуске размер снова исходный.

Приложение ещё не в проде, поэтому **BREAKING**-замена ключа конфигурации безопасна: ломать нечего, миграция старых `.env` не нужна.

## What Changes

- **BREAKING**: ключ `.env` `SKIP_COVER` заменяется на `EMBED_COVER` с противоположным смыслом: дефолт `true` (обложку встраиваем), `EMBED_COVER=false` отключает только обложку, текстовые теги пишутся как обычно. Старый `SKIP_COVER` перестаёт читаться, невалидное значение нового ключа игнорируется (флаг остаётся включённым).
- Поле `config.Config.SkipCover` → `EmbedCover`, `tagger.Adapter` получает `embedCover`, биндинг настроек — `EmbedCover`.
- Чекбокс в окне настроек: подпись «Встраивать обложку (текстовые теги пишутся)», по умолчанию включён.
- Удаляется мёртвое поле `downloader.Client.SkipCover` — его не читает ни один код (аналогично уже удалённому `FORMAT`).
- Первый запуск без сохранённого размера — окно 864×576 (+20% к текущим 720×480).
- Размер окна запоминается: при закрытии текущий размер пишется в `.env` (`WINDOW_WIDTH`, `WINDOW_HEIGHT`) и восстанавливается при следующем запуске. Развёрнутое окно не сохраняется — остаётся последний обычный размер.
- `.env.example` и `CHANGELOG.md` (секция `## [Unreleased]`) обновляются под новые ключи.
