## Purpose

Индексация музыкальной коллекции пользователя (папка из `LIBRARY_DIR` и папка загрузок), чтобы ещё до скачивания находить возможные дубли по нечёткому совпадению исполнителя и названия, а не только по точному имени файла.

## Requirements

### Requirement: Конфигурация через LIBRARY_DIR

Приложение MUST читать параметр `LIBRARY_DIR` из `.env`; параметр MUST также быть настраиваемым из окна настроек (см. capability `app-settings`) с горячим применением без перезапуска. Если параметр отсутствует или пуст — индексация коллекции и проверка дублей MUST быть выключены полностью (ни сканирования, ни диалогов, ни строк `[index]` в логе). Если включён `FLAC_MONITOR` (см. capability `quality-upgrade`), приложение MUST индексировать `OUTPUT_DIR` и без `LIBRARY_DIR`, но проверка дублей MUST оставаться выключенной. Если путь указан, но не существует, приложение MUST сообщить об этом в логе на русском и продолжить работу без проверки дублей.

#### Scenario: Параметр задан

- **WHEN** в `.env` задан `LIBRARY_DIR=D:\Music` и путь существует
- **THEN** при запуске приложение индексирует указанную папку и проверяет ссылки перед скачиванием

#### Scenario: Параметр не задан

- **WHEN** `LIBRARY_DIR` отсутствует в `.env` или пуст, а `FLAC_MONITOR` выключен
- **THEN** приложение работает ровно как раньше: без индексации, без строк `[index]` и без диалогов о дублях

#### Scenario: Мониторинг без LIBRARY_DIR

- **WHEN** `LIBRARY_DIR` пуст, а `FLAC_MONITOR` включён
- **THEN** приложение индексирует `OUTPUT_DIR` для мониторинга, но диалоги о дублях и проверка перед скачиванием остаются выключенными

#### Scenario: Путь не существует

- **WHEN** `LIBRARY_DIR` указывает на несуществующую папку
- **THEN** в логе появляется сообщение об ошибке пути на русском, приложение продолжает работать без проверки дублей

#### Scenario: Путь изменён в настройках

- **WHEN** пользователь указал новый `LIBRARY_DIR` в окне настроек и сохранил
- **THEN** без перезапуска запускается индексация новой папки (в фоне, с прогрессом в логе), проверка дублей работает по новому пути

#### Scenario: Путь очищен в настройках

- **WHEN** пользователь сохранил настройки с пустым `LIBRARY_DIR`, а `FLAC_MONITOR` выключен
- **THEN** индексация и диалоги о дублях выключаются до тех пор, пока путь не задан снова

### Requirement: Обход коллекции с подкаталогами

Приложение MUST индексировать `LIBRARY_DIR` рекурсивно, включая все подкаталоги, и MUST автоматически включать `OUTPUT_DIR` в тот же индекс, чтобы файлы, скачанные текущей сессией, сразу считались частью коллекции. Из индекса исключаются не-аудио файлы. Для каждого файла сохраняются путь, размер, время изменения, исполнители, заголовок и расширение.

#### Scenario: Подкаталоги учитываются

- **WHEN** в `D:\Music\Рок\` лежит файл, похожий на скачиваемый трек
- **THEN** он находится индексом, хотя и не лежит в корне коллекции

#### Scenario: Скачанное сразу в индексе

- **WHEN** приложение только что скачало трек в `OUTPUT_DIR`, а пользователь тут же вставляет ссылку на него же
- **THEN** повторное скачивание определяется как возможный дубль

#### Scenario: Не-аудио файлы игнорируются

- **WHEN** в папке коллекции лежат обложки, плейлисты и текстовые файлы
- **THEN** они не попадают в индекс и не влияют на проверку

### Requirement: Теги как источник, имя файла как запасной вариант

Для каждого аудиофайла источником исполнителя и заголовка MUST служить содержимое тегов (ID3v2/Vorbis/MP4); только если теги отсутствуют или нечитаемы, приложение MUST разбирать имя файла. Файл, у которого не удалось получить ни теги, ни осмысленное имя, MUST исключаться из сопоставления, но оставаться в индексе как путь.

#### Scenario: Теги читаются

- **WHEN** у файла есть теги с исполнителем и названием
- **THEN** для сопоставления используются значения из тегов независимо от того, как файл назван на диске

#### Scenario: Тегов нет

- **WHEN** у файла теги отсутствуют, но имя вида `Исполнитель - Название.flac` даёт заголовок
- **THEN** для сопоставления используются исполнитель и заголовок, разобранные из имени файла

#### Scenario: Ни тегов, ни смысла в имени

- **WHEN** файл называется `track001` и тегов не имеет
- **THEN** файл не участвует в сопоставлении и не может дать ложное предупреждение

### Requirement: Кэш индекса и инкрементальное обновление

Приложение MUST хранить индекс в кэш-файле рядом с exe и при последующих запусках MUST ограничиваться проверкой размера и времени изменения файлов, перечитывая теги только для новых, изменённых и удаляющихся файлов. Полное сканирование с чтением тегов MUST выполняться только при отсутствии кэша.

#### Scenario: Первый запуск

- **WHEN** кэш-файла ещё нет
- **THEN** выполняется полное сканирование коллекции с чтением тегов, результат сохраняется в кэш

#### Scenario: Повторный запуск

- **WHEN** кэш есть и файлы не менялись
- **THEN** индекс готовится без чтения тегов (только по размеру и времени изменения)

#### Scenario: Файлы менялись

- **WHEN** часть файлов добавлена, изменена или удалена после прошлого запуска
- **THEN** перечитываются только эти файлы, удалённые исключаются из индекса

### Requirement: Индексация в фоне с информированием

Полное сканирование MUST идти в фоне, не блокируя окно: пользователь может вставлять ссылки во время индексации. Приложение MUST информировать о ходе в логе (начало, счётчик обработанных файлов, готовность). Если ссылка обработана до завершения индексации, проверка MUST выполняться по уже проиндексированной части, а в лог MUST выводиться честное предупреждение, что проверка неполная.

#### Scenario: Ход сканирования виден

- **WHEN** идёт первое полное сканирование большой коллекции
- **THEN** в логе появляются строки вида `[index] сканирование коллекции D:\Music: 1240/5000 файлов...`, а по завершении — строка о готовности индекса

#### Scenario: Ссылка во время индексации

- **WHEN** пользователь вставил ссылку, пока индексация ещё не закончилась
- **THEN** проверка выполняется по уже проиндексированным файлам, в логе есть предупреждение, что индексация идёт и проверка неполная, окно при этом не блокируется

### Requirement: Нормализация имён по правилу сортировки

Сопоставление MUST работать на нормализованных значениях: регистр не важен, `ё`/`е` эквивалентны, пробелы и типы дефисов схлопываются, сортировочные артефакты правила кириллицы (префикс `ι `, замена первого символа на кириллический двойник) MUST сводиться к общему канону с обеих сторон, ведущий номер трека в имени файла MUST отбрасываться. Список исполнителей MUST рассматриваться как множество: разный порядок исполнителей MUST давать совпадение.

#### Scenario: Разный порядок исполнителей

- **WHEN** в коллекции лежит `Исполнитель B, Исполнитель A - Песня.flac`, а скачивается трек «Исполнитель A, Исполнитель B — Песня»
- **THEN** порядок не мешает: это считается совпадением и вызывает предупреждение о дубле

#### Scenario: Сортировочный префикс не ломает проверку

- **WHEN** файл в коллекции называется `ι Noize MC - Светлая полоса.flac`, а скачиваемый трек — «Noize MC — Светлая полоса»
- **THEN** префикс `ι ` снимается с обеих сторон и совпадение находится

#### Scenario: Латинский двойник первым символом

- **WHEN** файл называется `Мari Sa - Моя Любовь.flac`, а в метаданных скачиваемого трека — «Mari Sa — Моя Любовь»
- **THEN** двойник `М`/`M` сводится к одному канону и совпадение находится

#### Scenario: Ниже порога — не дубль

- **WHEN** названия отличаются настолько, что схожесть ниже заданного порога
- **THEN** предупреждение о дубле не показывается

### Requirement: Поиск по схожести, а не по точному равенству

Поиск кандидатов MUST основываться на нечёткой схожести строк (порог порядка 90–95% для обычного совпадения), чтобы ловить разные написания и мелкие вариации. Сильное совпадение названия трека MUST считаться кандидатом на дубль даже при разных исполнителях, чтобы отлавливать каверы и альтернативные версии. Режим порога не является вердиктом: приложение MUST показывать результат как вероятный дубль («возможно», с процентом совпадения), а не как точное определение.

#### Scenario: Кавер с тем же названием

- **WHEN** в коллекции уже есть «Песня» другого исполнителя, и вставляется ссылка на «Песню» с иным исполнителем
- **THEN** показывается предупреждение о возможном дубле с указанием обоих вариантов

#### Scenario: Вероятность, а не приговор

- **WHEN** найдено совпадение схожести 93%
- **THEN** текст предупреждения сообщает, что дубль возможен и совпадение неполное (процент указан), решение остаётся за пользователем

### Requirement: Учёт Radio Edit при поиске дублей

При проверке дублей приложение MUST сравнивать базовые названия, отбрасывая хвостовую пометку Radio Edit — в скобках, квадратных скобках и без них, в том числе с именем ремиксера перед ней. Совпадение базовых названий MUST показываться как возможный дубль с уверенностью около 95%, только если исполнитель совпадает или его схожесть не ниже обычного порога. Другие пометки версий и служебные пометки MUST NOT отбрасываться.

#### Scenario: Radio Edit без скобок

- **WHEN** в коллекции есть «Eminem — Not Afraid», а пользователь скачивает «Eminem — Not Afraid Radio Edit»
- **THEN** показывается окно «Возможен дубль» с уверенностью 95%, названием скачиваемого трека, именем и полным путём найденного файла; скачивание начинается только после «Скачать всё равно»

#### Scenario: Radio Edit в скобках

- **WHEN** в коллекции есть «Song», а скачивается «Song (Radio Edit)» или «Song [Radio Edit]»
- **THEN** файл считается возможным дублем

#### Scenario: Radio Edit с именем ремиксера

- **WHEN** в коллекции есть «Song», а скачивается «Song (2-4 Grooves Radio Edit)»
- **THEN** файл считается возможным дублем

#### Scenario: Другой исполнитель

- **WHEN** в коллекции есть «Artist A — Song», а скачивается «Artist B — Song (Radio Edit)»
- **THEN** предупреждение о дубле не показывается

#### Scenario: Радиоверсия, а не Radio Edit

- **WHEN** в коллекции есть «Song», а скачивается «Song (Radio Version)», «Song (Radio Mix)» или «Song (Radio Remix)»
- **THEN** предупреждение о дубле не показывается

#### Scenario: Другие версии не считаются

- **WHEN** в коллекции есть «Song», а скачивается «Song (Remix)», «Song (Live)», «Song (Remastered)» или «Song (Version)»
- **THEN** предупреждение о дубле не показывается

#### Scenario: Служебные пометки не отбрасываются

- **WHEN** в коллекции есть «Song (m4a) [ФАКТ 320]», а скачивается «Song»
- **THEN** предупреждение о дубле не показывается

#### Scenario: Название состоит только из Radio Edit

- **WHEN** название после снятия пометки становится пустым
- **THEN** такое название не даёт совпадений и не вызывает паники

#### Scenario: Поиск лучшего качества не меняется

- **WHEN** мониторинг качества сравнивает локальный «Song» с результатом поиска «Song (Live)»
- **THEN** live-версия не считается кандидатом на замену: правило Radio Edit действует только для проверки дублей

### Requirement: Yandex ID и source URL в индексе

Для каждого аудиофайла индекс MUST сохранять Yandex ID и source URL, извлекая их из `YANDEX_TRACK_ID` (FLAC), UFID или COMM (MP3), source-url (M4A) либо разбирая URL. Отсутствие ID MUST NOT исключать файл из индекса и проверки дублей; файл без ID MAY участвовать в мониторинге через поиск по исполнителю и названию.

#### Scenario: FLAC с YANDEX_TRACK_ID

- **WHEN** в FLAC есть Vorbis comment `YANDEX_TRACK_ID`
- **THEN** индекс сохраняет этот ID и source URL из `COMMENT`

#### Scenario: MP3 с source-url

- **WHEN** в MP3 есть COMM с описанием `yandex-music-downloader:source-url`
- **THEN** индекс извлекает ID трека из URL

#### Scenario: Внешний файл без ID

- **WHEN** у MP3 нет ни Yandex ID, ни source URL, но есть исполнитель и название
- **THEN** файл остаётся в индексе для проверки дублей и может участвовать в мониторинге через поиск по названию

### Requirement: Исключение _old из индекса

Каталог `_old` в корне `LIBRARY_DIR` или `OUTPUT_DIR` и любые вложенные `_old` MUST исключаться из обхода. Файлы в нём MUST NOT участвовать в проверке дублей и мониторинге качества; их изменение MUST NOT влиять на индекс.

#### Scenario: Старый MP3 не считается дублем

- **WHEN** обновлённый трек лежит в `_old`, а пользователь снова скачивает этот же трек
- **THEN** файл из `_old` не вызывает предупреждение о дубле

#### Scenario: Файл вернули из _old

- **WHEN** пользователь переместил файл из `_old` обратно в коллекцию
- **THEN** следующее обновление индекса снова видит его как обычный аудиофайл
