# Spec Delta

## ADDED Requirements

### Requirement: Компоновка окна настроек

Форма настроек MUST быть разбита на именованные секции: аккаунт, папки, качество, теги, производительность и мониторинг. При минимальном размере окна кнопки «Сохранить» и «Отмена» MUST оставаться видимыми без прокрутки, а форма MUST NOT требовать горизонтальной прокрутки. Подписи MUST объяснять назначение параметра; технический ключ `.env` MUST NOT быть единственной подписью.

#### Scenario: Секции и видимое сохранение

- **WHEN** пользователь открыл настройки при минимальном размере окна
- **THEN** параметры сгруппированы по именованным секциям, кнопки «Сохранить» и «Отмена» видны без прокрутки, горизонтальной прокрутки нет

#### Scenario: Понятная подпись параметра

- **WHEN** пользователь читает форму настроек
- **THEN** у каждого параметра есть русская подпись, объясняющая его назначение, а технический ключ `.env` не является единственной подписью

### Requirement: Защита от потери изменений

Если в форме есть несохранённые изменения, закрытие по Escape, клику на фон или крестику MUST требовать подтверждения. Если изменений нет, окно MUST закрываться без вопроса. Кнопка «Отмена» MUST закрывать окно без сохранения и без дополнительного вопроса.

#### Scenario: Закрытие с изменениями

- **WHEN** пользователь изменил токен или путь и нажал Escape
- **THEN** появляется вопрос о закрытии без сохранения; при отказе форма остаётся открытой с введёнными значениями

#### Scenario: Закрытие без изменений

- **WHEN** пользователь открыл настройки и ничего не менял, затем нажал Escape или кликнул по фону
- **THEN** окно закрывается без вопроса

#### Scenario: Явная отмена

- **WHEN** пользователь изменил значения и нажал «Отмена»
- **THEN** окно закрывается, изменения не сохраняются, повторный вопрос не показывается

### Requirement: Доступность окна настроек

При открытии фокус MUST перемещаться в первое поле формы. Tab MUST циклически оставаться внутри окна. Окно MUST иметь роль диалога, `aria-modal` и доступное имя. Ошибки формы MUST объявляться через `aria-live`. После закрытия фокус MUST возвращаться в поле ссылки.

#### Scenario: Фокус при открытии

- **WHEN** пользователь открыл настройки
- **THEN** фокус находится в первом поле формы, а не остаётся на скрытом элементе главного экрана

#### Scenario: Tab не выходит из окна

- **WHEN** пользователь многократно нажимает Tab внутри открытых настроек
- **THEN** фокус циклически переходит между элементами формы и не уходит на главный экран

#### Scenario: Ошибка формы для скринридера

- **WHEN** сохранение отклонено из-за неверного числа воркеров или пустой папки
- **THEN** сообщение об ошибке объявляется через `aria-live` и остаётся видимым рядом с формой

#### Scenario: Escape закрывает окно

- **WHEN** пользователь нажал Escape в настройках без несохранённых изменений
- **THEN** окно закрывается, фокус возвращается в поле ссылки
