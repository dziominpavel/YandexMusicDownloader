# Spec Delta

## MODIFIED Requirements

### Requirement: Время последней проверки

Приложение MUST сохранять время последней завершённой проверки и её результат (найдено N / ничего не найдено / ошибка) и MUST обновлять их после каждой проверки. Эти данные MUST быть доступны окну настроек и бейджу на кнопке «Настройки» без повторного запроса к API и MUST сохраняться между запусками. После завершения проверки индикация MUST показывать фактический результат, а не состояние выполнения.

#### Scenario: Проверка завершилась

- **WHEN** проверка завершилась и нашла 3 трека
- **THEN** в журнале сохраняются время завершения и результат «найдено 3», которые показывают настройки и бейдж

#### Scenario: Приложение перезапущено

- **WHEN** приложение запущено после проверки
- **THEN** настройки показывают сохранённые время и результат без новой проверки

#### Scenario: Проверка завершилась ошибкой

- **WHEN** проверка остановилась из-за токена, прав или сети
- **THEN** сохраняются время попытки и результат «ошибка», а причина доступна в логе

#### Scenario: Индикация не остаётся в состоянии выполнения

- **WHEN** проверка завершилась без находок
- **THEN** индикация показывает «ничего не найдено», а не «проверка идёт»

### Requirement: Триггеры проверки

Приложение MUST иметь настройку `FLAC_MONITOR` (по умолчанию выключена) и ручную команду «Проверить сейчас» в разделе мониторинга окна настроек. При включённой настройке проверка MUST запускаться при старте, если с последней прошло не менее 7 дней, и раз в 7 дней, пока окно открыто. При закрытом приложении проверок нет. Если токен пуст/невалиден или нет Плюса, проверка MUST завершаться сообщением и MUST NOT создавать ложных статусов.

#### Scenario: Ручная проверка

- **WHEN** пользователь нажал «Проверить сейчас» в настройках
- **THEN** проверка запускается независимо от значения `FLAC_MONITOR`

#### Scenario: Автопроверка на старте

- **WHEN** `FLAC_MONITOR=true` и с последней успешной проверки прошло 7 дней
- **THEN** после готовности индекса запускается проверка в фоне, не блокируя окно

#### Scenario: Срок не наступил

- **WHEN** `FLAC_MONITOR=true` и последняя проверка была вчера
- **THEN** проверка не запускается и в лог не пишется лишних строк

#### Scenario: Нет Плюса

- **WHEN** токен валиден, но у аккаунта нет Плюса
- **THEN** проверка завершается сообщением, что lossless недоступен для аккаунта, и не помечает треки как «FLAC нет»

### Requirement: Окно найденного

При находке приложение MUST сохранить список и показать бейдж количества на кнопке «Настройки»; окно MUST открываться из настроек. Окно MUST показывать локальный файл, текущий и найденный форматы и папку назначения нового FLAC (`OUTPUT_DIR`); для поисковых совпадений — трек, альбом, год и процент. ID-совпадения MUST быть предвыбраны, поисковые — только при уверенном совпадении. Для каждого поискового совпадения MUST быть действие «Не тот трек», которое убирает строку и сохраняет отклонение без скачивания; для ID-совпадений действие MUST NOT показываться. После отклонения сводка и бейдж MUST обновляться, а если строк не осталось — окно MUST закрываться. Действия: «Скачать все», «Показать список», «Позже»; «Позже» MUST сохранять список и бейдж. При отсутствии находок окно MUST NOT показываться.

#### Scenario: Много ID-совпадений

- **WHEN** проверка нашла 67 треков по ID
- **THEN** окно показывает сводку «Найдено 67 треков», все предвыбраны, доступны «Скачать все» и «Показать список»

#### Scenario: Поисковые совпадения

- **WHEN** найдены треки без ID
- **THEN** они показаны отдельно с найденным треком, альбомом, годом и процентом; предвыбраны только уверенные совпадения

#### Scenario: Ничего не найдено

- **WHEN** проверка не нашла ни одного lossless-варианта
- **THEN** окно не показывается, в логе остаётся итоговая строка проверки

#### Scenario: Позже

- **WHEN** пользователь нажал «Позже»
- **THEN** окно закрывается, найденное сохраняется, а на кнопке «Настройки» остаётся бейдж с количеством

#### Scenario: Отклонение в окне

- **WHEN** пользователь нажал «Не тот трек» у поискового совпадения
- **THEN** строка исчезает из списка, файл не скачивается, отклонение сохраняется, а бейдж уменьшается на единицу

#### Scenario: Последнее совпадение отклонено

- **WHEN** пользователь отклонил единственное оставшееся поисковое совпадение
- **THEN** окно закрывается, а бейдж скрывается

#### Scenario: ID-совпадение не отклоняется

- **WHEN** найденный элемент получен по Yandex ID
- **THEN** действие «Не тот трек» для него не показывается

#### Scenario: Открытие из настроек

- **WHEN** есть найденные треки, пользователь открыл настройки и нажал «Открыть найденное»
- **THEN** открывается окно со сводкой и списком

#### Scenario: Папка назначения видна

- **WHEN** в списке есть MP3 из папки коллекции
- **THEN** окно показывает, что новый FLAC будет скачан в `OUTPUT_DIR`, а старый MP3 перемещён в `_old`

### Requirement: Обновление файла

По подтверждению приложение MUST скачать lossless в `OUTPUT_DIR` (с учётом `SUBDIRS` и обычного имени `Исполнитель - Название.ext`), при `flac-mp4` конвертировать в FLAC, если ffmpeg доступен, иначе сохранить lossless `.m4a`, записать теги и атомарно опубликовать. Новый аудиофайл MUST NOT попадать в `LIBRARY_DIR`. Только после успешной публикации старый MP3 MUST быть перемещён в `<корень старого файла>\_old\<относительный путь>`, а его `.lrc` — вместе с ним. При MP3-fallback или ошибке публикации старый файл MUST NOT перемещаться. При занятом имени в `_old` MUST добавляться метка времени.

#### Scenario: MP3 заменён на FLAC

- **WHEN** пользователь подтвердил обновление MP3 из `LIBRARY_DIR`, сервер отдал `flac` или `flac-mp4`, а ffmpeg доступен
- **THEN** новый `.flac` с тегами появляется в `OUTPUT_DIR`, старый MP3 перемещается в `LIBRARY_DIR\_old`, новых аудиофайлов в `LIBRARY_DIR` нет

#### Scenario: MP3 из загрузок обновлён

- **WHEN** пользователь подтвердил обновление MP3 из `OUTPUT_DIR`
- **THEN** новый `.flac` появляется в `OUTPUT_DIR`, старый MP3 перемещается в `OUTPUT_DIR\_old`

#### Scenario: Сайдкар старого файла

- **WHEN** рядом со старым MP3 есть `.lrc`
- **THEN** файл `.lrc` перемещается в `_old` вместе со старым MP3

#### Scenario: Lossless снова пропал

- **WHEN** во время обновления сервер вернул MP3-fallback
- **THEN** новый MP3 не публикуется как обновление, старый файл остаётся на месте, в логе указана причина

#### Scenario: Ошибка публикации

- **WHEN** скачивание или тегирование завершилось ошибкой
- **THEN** временный файл удаляется, старый файл остаётся на месте, в логе есть ошибка

#### Scenario: Имя в _old занято

- **WHEN** в `_old` уже есть файл с тем же относительным путём
- **THEN** старый файл сохраняется под именем с меткой времени, новый FLAC остаётся в `OUTPUT_DIR`

### Requirement: Существующий FLAC и повторный запуск

Если FLAC с тем же треком уже есть рядом со старым MP3 или в `OUTPUT_DIR`, приложение MUST NOT скачивать второй; оно MUST проверить, что это тот же трек, и предложить только переместить дубль MP3 в `_old`. После успешного обновления файл MUST исчезнуть из кандидатов. Прерванная job'а MUST сохранять уже обновлённые файлы и при следующем запуске продолжать с необновлённых.

#### Scenario: FLAC уже лежит рядом

- **WHEN** рядом с MP3 уже есть `.flac` с тем же треком
- **THEN** повторного скачивания нет, предлагается только переместить MP3 в `_old`

#### Scenario: FLAC уже есть в загрузках

- **WHEN** в `OUTPUT_DIR` уже есть `.flac` с тем же треком, а старый MP3 лежит в `LIBRARY_DIR`
- **THEN** повторного скачивания нет, старый MP3 перемещается в `LIBRARY_DIR\_old`

#### Scenario: Остановка посреди пачки

- **WHEN** пользователь остановил обновление после нескольких треков
- **THEN** уже обновлённые файлы остаются, незавершённые не считаются обновлёнными, следующая проверка продолжает с них

#### Scenario: Повторная проверка после обновления

- **WHEN** трек уже обновлён до `.flac`
- **THEN** он больше не появляется в списке найденного
