# Design

## Context

`library.FindMatches` сравнивает полные названия, нормализованные `norm.Comparable`: Левенштейн ≥0.90 либо ≥0.80 при схожести исполнителей ≥0.90. Пометка `Radio Edit` в хвосте названия не снимается, поэтому «Not Afraid Radio Edit» и «Not Afraid» проходят как разные песни. `ScoreCandidate` (поиск лучшего качества) использует тот же `Comparable`, и тест требует, чтобы live/remix не считались одним треком для апгрейда. Аудит коллекции — в `review.md`; по решению пользователя в область входит только `Radio Edit`, остальные пометки (remix/live/remastered/version, m4a/ФАКТ) — ложные и не трогаются.

## Goals / Non-Goals

**Goals:**

- Снимать хвостовую пометку `Radio Edit` (без скобок, в скобках/квадратных скобках, в том числе с именем ремиксера перед ней).
- Показывать радиоверсию того же исполнителя как «Возможен дубль» с уверенностью 95%.
- Не менять точное/нечёткое сравнение, `ScoreCandidate`, кэш, UI и формат файлов.

**Non-Goals:**

- Снимать remix, live, remastered, version, radio version/mix/remix, m4a, ФАКТ, ИСКАЖЕН, feat., II, Part 2, отдельный год.
- Показывать 50%-подсказки для отклонённых версий: пользователь признал эти пары ложными, подсказки только добавляют шум.
- Удалять/объединять файлы автоматически.
- Менять схему кэша или строить новую фонетическую схожесть.

## Decisions

### 1. Отдельная функция `norm.RadioEditBase`, а не правка `Comparable`

Добавляется `norm.RadioEditBase(title string) string` — нормализованное название без хвостового `Radio Edit`. `Comparable` остаётся прежним.

Почему: `Comparable` используется в `ScoreCandidate`, сортировке и именах файлов; глобальное снятие пометок — регрессия для поиска лучшего качества. `RadioEditBase` вызывает `Comparable`, поэтому обе стороны сравнения нормализуются одинаково.

Альтернативы: общий `BaseTitle` со всеми версиями/служебными пометками (первая редакция) — отклонён пользователем; хранить базовое название в `Entry` и поднимать версию кэша — лишний полный перескан коллекции, поле можно добавить позже.

### 2. Что именно снимается

1. `Comparable` приводит название к нижнему регистру, убирает `ё`/двойники/дефисы/кавычки, схлопывает пробелы.
2. Если хвост — группа в скобках `(…)`/`[…]` и её содержимое содержит фразу `radio edit`, группа снимается целиком. Это покрывает `(Radio Edit)`, `[Radio Edit]`, `(2-4 Grooves Radio Edit)` и повторные группы.
3. Иначе, если название заканчивается на ` radio edit` (в том числе после дефиса, который `Comparable` уже заменил пробелом), фраза снимается. Это покрывает `Not Afraid Radio Edit` и `Redlight Radio Edit`.
4. Хвостовые разделители срезаются; пустой результат означает «название состоит только из пометки» и в сравнении не участвует.

Снимается **только** `radio edit`. `Radio Version`, `Radio Mix`, `Radio Remix`, `Remix`, `Live`, `Remastered`, `Version`, `m4a`, `ФАКТ NNN`, `ИСКАЖЕН` не отбрасываются. Если после `Radio Edit` стоит другая пометка (`Song (Radio Edit) [ФАКТ 320]`), хвост не распознаётся и совпадения нет — это осознанная плата за отказ от снятия служебных пометок.

### 3. Fallback в `FindMatches`

- Сначала работает текущая логика полного названия; она не меняется.
- Если файл не прошёл её, считаются `baseQuery := norm.RadioEditBase(title)` и `entryBase := norm.RadioEditBase(e.Title)`. При равенстве базовых названий, различии полных названий и схожести исполнителей ≥0.90 добавляется `Match{Percent: 95}`.
- Исполнитель обязателен: радиоверсия того же трека — это тот же исполнитель; версия другого артиста — кавер, и этот fallback его не ловит. Существующее правило сильного названия по-прежнему ловит каверы с точным названием, так что поведение для них не меняется.
- 95, а не 100: название отличается пометкой; окно уже говорит «возможен дубль». Одна запись добавляется один раз, сортировка и `maxMatches` прежние.

### 4. Без миграции кэша

`RadioEditBase` вычисляется на лету только для записей, не прошедших полное сравнение. На 3000 файлах это малые строки и одна проверка; кэш v2 остаётся совместимым, полного перескана при обновлении нет.

## Risks / Trade-offs

- **`Radio Version`/`Radio Mix` не ловятся** → так решил пользователь: это не `Radio Edit`; при необходимости добавляется отдельно.
- **`Radio Edit` перед другой пометкой не ловится** (`Song (Radio Edit) [ФАКТ 320]`) → следствие отказа снимать служебные пометки; такие теги лучше чистить.
- **Кросс-исполнительские радиоверсии не ловятся** → снижает ложные срабатывания; каверы с точным названием по-прежнему ловит старое правило.
- **Песня, которая буквально заканчивается на «Radio Edit»** → редкий ложный кандидат, 95% и без автоудаления.
- **Схожесть исполнителей ниже порога** из-за разных написаний → обычное сравнение названий остаётся; радиоверсия может не сработать, это консервативно.
- **50%-подсказки для остальных версий** не включаем: пользователь считает их ложными; если понадобятся, это отдельное изменение.

## Migration Plan

Изменение чисто кодовое: пересборка exe и перезапуск приложения. Кэш индекса и файлы коллекции не мигрируются; откат — revert коммита. Пользовательская запись — в `CHANGELOG.md` (`[Unreleased]`, «Исправлено»), версия не бампится.
