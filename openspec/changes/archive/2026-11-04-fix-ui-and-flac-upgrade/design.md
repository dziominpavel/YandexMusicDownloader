# Design

## Context

Сейчас `downloader.Client.Upgrade` вычисляет путь нового файла из старого: берёт `oldPath`, отбрасывает расширение и кладёт результат рядом (`src/internal/downloader/lossless.go`). `quality.Upgrader` уже знает `OutputDir`, но не передаёт его в загрузчик. Поэтому обновление MP3 из `LIBRARY_DIR` публикует FLAC в коллекции, хотя `track-download` требует писать в `OUTPUT_DIR`.

Остальные дефекты локализованы:

- `qualityStatusView` читает флаг `checking` до того, как `runQualityCheck` сбрасывает его в `defer`, поэтому событие `quality-check-finished` несёт текст «FLAC: проверка идёт…».
- Wails загружает иконку окна по числовому ID 3 (`winc.AppIconID`), а `go-winres` пишет группу с именем `APP`; `LoadImage` не находит ресурс и оставляет стандартную иконку Windows.
- Кнопка FLAC, её бейдж и строка статуса живут в шапке, хотя проверка уже есть в настройках; «Проверить сейчас» закрывает форму, а `quality-found` автоматически открывает модалку.

Настройки папок и чекбокс «Папка загрузок отличается от папки коллекции» в этом change не меняются.

## Goals / Non-Goals

**Goals:**

- Любая загрузка, включая FLAC-обновление, публикуется в `OUTPUT_DIR`; новый аудиофайл никогда не попадает в `LIBRARY_DIR`.
- Старый MP3 и его `.lrc` сохраняются в `_old` в корне старого файла.
- Убрать FLAC-кластер из шапки, оставить проверку и статус в настройках, а количество найденного — бейджем на «Настройках».
- Показывать после проверки фактический результат, а не «проверка идёт…».
- Вернуть нормальную иконку в панель задач и нормальную шестерёнку.

**Non-Goals:**

- Менять семантику `LIBRARY_DIR`/`OUTPUT_DIR` и чекбокс их равенства.
- Автоматически переносить скачанный FLAC из `OUTPUT_DIR` в коллекцию.
- Менять правила дублей, индекс, `_old`-очистку и формат журнала.
- Добавлять новые настройки или зависимости.

## Decisions

### 1. Новый FLAC всегда в OUTPUT_DIR

`downloader.Upgrade` получает папку назначения явно:

```
Upgrade(ctx, track, oldPath, destDir, onProgress)
  ...
  ext, format := upgradeTarget(...)
  dest := c.destPath(destDir, track, ext)   // обычное имя + SUBDIRS
```

`quality.Upgrader` передаёт свой `OutputDir`. Старый файл в путь назначения не влияет: он нужен только для `_old` и проверки «FLAC уже есть».

Почему не оставить имя старого файла и поменять только папку: старые имена часто содержат хвосты качества (`[ФАКТ 320]`), а обычное имя совпадает с тем, что пользователь увидел бы при обычной загрузке. Почему не скачивать рядом со старым и потом переносить: перенос между дисками — это копирование, а не атомарный `rename`, плюс временный файл оказался бы в коллекции.

`destPath` уже учитывает `SUBDIRS`/`SUBDIR_TEMPLATE`, поэтому подпапки работают и для обновлений. Проверка `os.Stat(dest)` и `ErrAlreadyExists`/`ErrDestConflict` остаются: они теперь смотрят на путь в `OUTPUT_DIR`.

### 2. `_old` остаётся в корне старого файла

`moveToOld` уже выбирает корень через `rootFor(oldPath)` (`LIBRARY_DIR`, затем `OUTPUT_DIR`) и перемещает файл в `<корень>\_old\<относительный путь>`. Это правило сохраняется: старый MP3 из коллекции уходит в `LIBRARY_DIR\_old`, старый MP3 из загрузок — в `OUTPUT_DIR\_old`.

Вместе с MP3 best-effort перемещается одноимённый `.lrc`, если он есть. Иначе в коллекции остался бы осиротевший `.lrc`, а новый FLAC лежал бы в другой папке. Ошибка перемещения `.lrc` не валит job'у: пишется `[warn]`, аудио уже опубликовано.

### 3. Существующий FLAC ищется по всему индексу

`quality.Pending` уже строит `flacByID` по всем корням индекса. Если FLAC с тем же `TrackID` есть рядом со старым MP3 или в `OUTPUT_DIR`, `AlreadyFlac` заполняется, и `upgrader` только архивирует MP3. Это поведение сохраняется; меняется лишь формулировка в спеке.

### 4. FLAC-флоу: настройки вместо шапки

Из шапки удаляются `qualityBtn`, `qualityBadge`, `qualityStatus`. Остаются папка и настройки; на кнопке настроек появляется бейдж `settingsBadge` с количеством найденного.

- `quality-found` и `quality-pending` только обновляют список, бейдж и статус. Модалка сама не открывается.
- «Проверить сейчас» в настройках остаётся на месте: форма не закрывается, несохранённые правки не теряются, кнопка блокируется на время проверки.
- После завершения в разделе показывается результат и действие «Открыть найденное (N)», которое открывает существующую модалку.
- `QualityStatusView` получает поле `OutputDir`, чтобы модалка и настройки могли показать папку назначения без отдельного запроса.

Альтернатива — оставить маленькую icon-only кнопку в шапке — отклонена: пользователь просил убрать дублирующее действие, а бейдж на настройках сохраняет видимость находок.

Альтернатива — оставить авто-открытие модалки при находке — отклонена: еженедельная фоновая проверка не должна перекрывать текущую работу. Бейдж и строка в настройках дают достаточно сигнала.

### 5. Статус завершения считается после сброса `checking`

`runQualityCheck` должен сбросить `checking` (и `checkCancel`) до формирования текста для `quality-check-finished`. Практически: вынести сброс в отдельный helper или вызвать его перед `qualityStatusView`. Событие завершения получает фактический результат: «найдено N», «ничего не найдено», «ошибка» или «проверка отменена».

Тест должен проверять именно текст события, а не только `QualityStatus()` после возврата: текущий тест этого не ловит.

### 6. Иконка окна: числовой ID 3 в ресурсах

В `assets/winres/winres.json` группа иконок переименовывается из `"APP"` в `"#3"`:

```json
"RT_GROUP_ICON": {
  "#3": { "0000": ["icon-16.png", "icon-32.png", "icon-48.png", "icon-256.png"] }
}
```

`go-winres` трактует `#3` как числовой ID, а Wails ищет именно ID 3. Explorer по-прежнему берёт первую группу (она единственная), поэтому иконка файла не меняется. Вызывать Win32 `SetIcon` из приложения не нужно: Wails делает это сам, когда находит ресурс.

### 7. Шестерёнка

`<symbol id="icon-settings">` заменяется на зубчатый контур (cog) с внутренним кругом, в том же `viewBox="0 0 24 24"`, `fill: none`, `stroke: currentColor`, `stroke-width: 1.75`. Никаких эмодзи и новых зависимостей.

### 8. Порядок относительно add-startup-animation

`add-startup-animation` уже правит `src/frontend/dist/index.html` и `app.css` (в рабочем дереве есть незакоммиченные изменения). Этот change затрагивает те же файлы. Применять его нужно после завершения/коммита стартовой анимации либо ребейзить правки поверх неё; в tasks это отмечено отдельным пунктом.

## Risks / Trade-offs

- **Коллекция теряет playable-файл**: после обновления MP3 из `LIBRARY_DIR` остаётся только в `_old`, а FLAC — в `OUTPUT_DIR`. Это следствие выбранного правила; пользователь переносит FLAC в коллекцию сам. → Явно писать это в окне найденного и в `docs/15-flac-monitor.md`.
- **Совпадение имени в OUTPUT_DIR**: если там уже есть FLAC другого трека с тем же именем, `ErrDestConflict` оставит старый MP3 на месте и покажет ошибку. → Сохранить текущую обработку и лог.
- **`.lrc` не переместился**: файл может быть занят. → `[warn]`, job'а не падает, старый MP3 всё равно архивируется.
- **Кэш иконки панели задач**: Windows может помнить старую иконку закреплённого ярлыка. → В проверке указать, что после пересборки нужно открепить/закрепить ярлык.
- **Конфликт с `add-startup-animation`**: правки в тех же файлах. → Сначала завершить существующий change или наложить этот поверх.
- **Тесты ожидают старое поведение**: `upgrader_test.go` проверяет файл рядом со старым. → Обновить ожидания на `OUTPUT_DIR` и `_old` в исходном корне.

## Migration Plan

- Миграции данных нет: `.env`, журнал и существующие `_old` остаются как есть.
- После обновления первый запуск ведёт себя по новым правилам; уже обновлённые ранее файлы не переобрабатываются.
- Откат: вернуть предыдущий exe. Файлы, уже опубликованные в `OUTPUT_DIR`, остаются; старые MP3 можно вернуть из `_old` вручную.
