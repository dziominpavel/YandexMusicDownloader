# Design

## Context

См. `proposal.md` — Why. Технический контекст, влияющий на подход:

- Окно настроек — оверлей `#settingsOverlay` в единственном файле `src/frontend/dist/index.html`; он встроен в exe через `//go:embed dist/*` (`src/frontend/embed.go`), отдельной сборки фронтенда нет.
- Поле токена — `input type="password" id="sToken"`; рядом кнопка «Проверить» и строка результата `#tokenCheck`.
- В Wails v2.15 доступен `window.runtime.BrowserOpenURL(url)` — он открывает URL в системном браузере. Бэкенд-биндинг для этого не нужен.
- Канонический URL OAuth и шаги уже зафиксированы в `docs/11-get-token.md`: `https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d`.
- Тексты без токена сейчас живут в `src/internal/ui/app.go`: стартовая строка `a.ready` и ответ `Download` при `a.client == nil`.
- Тестов фронтенда нет; проверка UI — ручная, бэкенд-тексты покрываются Go-тестами.

## Goals / Non-Goals

**Goals:**

- Показать справку ровно там, где пользователь вводит токен, не раздувая форму настроек.
- Дать самодостаточную инструкцию, которая работает без docs/ и без сети (кроме самой страницы Яндекса).
- Не менять существующий поток сохранения настроек и проверки токена.
- Убрать из сообщений без токена совет править `.env` вручную — он ведёт мимо окна настроек.

**Non-Goals:**

- Автоматическое получение токена (Device Flow / `device_auth`) — отдельный change.
- Хранение токена в Windows Credential Manager.
- Ссылка на GitHub-документацию из справки — встроенный текст должен быть самодостаточным.
- Переработка окна настроек целиком, Esc для самого окна настроек, фокус-ловушка.

## Decisions

**1. Постоянная ссылка под полем + отдельный оверлей справки, а не инструкция в форме.**
Ссылка «Как получить токен?» видна всегда, поэтому справка находится в момент нужды. Сама инструкция — второй оверлей поверх настроек: форма остаётся компактной, введённые значения не теряются, а паттерн модалки уже используется в приложении.
Альтернативы:
- *Развернуть инструкцию прямо в форме* — отклонена: 5 шагов и предупреждения уводят кнопку «Сохранить» далеко вниз, а инструкция нужна один раз.
- *Отдельная страница настроек* — отклонена: лишняя навигация и состояние.
- *Ссылка на `docs/11-get-token.md`* — отклонена: рядом с exe документации нет, а интернет нужен и так только для OAuth.

**2. Пустой токен — предупреждение в форме, но без автооткрытия справки.**
При открытии настроек JS смотрит на `s.Token`: если пусто, под полем показывается «Без токена доступно только 30-секундное превью» и та же ссылка. Автооткрытие модалки при первом входе отклонено: оно перекрывает форму и выглядит навязчиво; последствие пустого токена достаточно объяснить строкой.

**3. OAuth-страница открывается системным браузером через `window.runtime.BrowserOpenURL`.**
URL — константа в JS, окно приложения не навигируется. Альтернативы:
- *`<a target="_blank">`* — отклонена: WebView2 может открыть ссылку внутри приложения или заблокировать переход.
- *Новый Go-биндинг* — отклонена: Wails уже даёт нужный runtime-метод, биндинг добавил бы код без пользы.

**4. Справка — статический HTML в `index.html`, без загрузки docs/ во время работы.**
Один exe не должен зависеть от файлов рядом. `go:embed` не умеет брать файлы из `docs/` (пакет `frontend`), а копирование при сборке усложнило бы процесс. Поэтому в модалку попадает сокращённый текст: зачем токен, 4 шага, подсказка про быстрый редирект, предупреждение о безопасности. `docs/11-get-token.md` остаётся расширенным руководством (способы 2–3, 401, отзыв токена) и обновляется ссылкой на новый путь через настройки.

**5. В справке явно сказано копировать только значение `access_token`, без префикса `access_token=`.**
Самая частая ошибка при копировании из адресной строки — вставить всю пару `access_token=...&token_type=...`; тогда «Проверить» вернёт ошибку. В шаге показывается пример строки и границы значения.

**6. Справка закрывается кнопкой, кликом по фону и `Esc`; окно настроек остаётся открытым.**
`Esc` вешается на `document` только пока справка открыта; настройки не трогаем, чтобы не менять их текущее поведение. Фокус после закрытия возвращается на ссылку «Как получить токен?» — клавиатурный сценарий остаётся предсказуемым.

**7. Тексты без токена в бэкенде ведут в настройки.**
`a.ready` при пустом токене и ответ `Download` при `a.client == nil` заменяются на подсказку «⚙ Настройки → Как получить токен?». Это убирает устаревший совет править `.env` вручную. В `app_test.go` проверяется, что сообщение содержит отсылку к настройкам; существующая проверка префикса `[error]` сохраняется.

**8. Обновляются пользовательские доки, но не `.env.example`.**
`docs/11-get-token.md`: в шаге «Положите токен» первым вариантом становится «вставить в окно настроек», ручное создание `.env` остаётся вторым. `docs/friends-setup.md`: шаг 2 переписывается на «запусти app.exe → ⚙ Настройки → вставь токен → Проверить → Сохранить». Новых ключей `.env` нет, поэтому `.env.example` не меняется.

## Risks / Trade-offs

- [Текст справки разойдётся с `docs/11-get-token.md`] → в модалке только короткий обязательный минимум; расширенные случаи остаются в доке, при изменении OAuth-инструкции править оба места. В HTML рядом с блоком — комментарий про источник.
- [Яндекс может не выдать токен через implicit flow] → в справке есть подсказка про инкогнито и `Ctrl+L`/`Ctrl+C`, а в доке — альтернативные способы; приложение не обещает, что способ сработает всегда.
- [Второй оверлей поверх первого: клики и `Esc` могут закрыть не то окно] → у справки собственный `z-index`, обработчик фона проверяет `e.target`, `Esc` обрабатывается только при открытой справке; ручная проверка сценария.
- [Модалка не влезет в маленькое окно] → карточка справки ограничена `max-height: 90vh` и скроллится, как карточка настроек.
- [Пользователь вставит токен с `access_token=` или пробелами] → «Проверить» покажет причину; в справке отдельный акцент на копирование только значения.
- [Токен остаётся в поле `type="password"` и не логируется] → справка не читает и не показывает значение токена; новых мест хранения нет.
