# Proposal

## Why

История последних ссылок не решает реальную задачу: альбом или плейлист скачивается один раз, а уже скачанное приложение и так пропускает. При этом нативный выпадающий список при фокусе закрывает лог, хранит сырые URL (а при пакетной вставке — всю строку целиком) и не даёт удалить или очистить записи. Ценность ниже стоимости поддержки.

## What Changes

- **BREAKING**: удаляется история последних ссылок: из поля ввода убирается `datalist`, а из фронтенда — чтение/запись `localStorage` и запись ссылки при старте скачивания.
- Поле ввода остаётся чистым: без выпадающего списка и без кнопки-стрелки, перекрывающей лог.
- Drag & drop, предпросмотр обложки/названия и кнопка «Открыть папку загрузок» сохраняются без изменений.
- Требование истории убирается из capability `track-download`; остальные UX-требования остаются.
- README и changelog обновляются: история больше не заявляется как возможность приложения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `track-download`: требование «UX улучшения без настроек» больше не включает историю последних ссылок; сценарий «История ссылок» удаляется.

## Impact

- `src/frontend/dist/index.html`: удалить `list="linkHistory"`, элемент `<datalist id="linkHistory">` и JS-блок истории (`HISTORY_KEY`, `loadHistory`, `renderHistory`, `rememberLink`, вызов `rememberLink`).
- `openspec/specs/track-download/spec.md`: обновить требование и удалить сценарий истории (через delta текущего change).
- `README.md`: убрать упоминание истории из списка возможностей.
- `CHANGELOG.md`: пользовательский пункт об удалении истории и инженерная деталь под `### Изменено`.
- Go-код не меняется: история реализована только во фронтенде, API приложения не затрагивается.
