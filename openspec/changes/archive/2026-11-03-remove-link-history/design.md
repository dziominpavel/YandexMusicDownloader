# Design

## Context

См. `proposal.md` — Why. История ссылок реализована целиком во фронтенде (`src/frontend/dist/index.html`): атрибут `list="linkHistory"` у поля ввода, элемент `<datalist>`, ключ `yamdl.linkHistory` в `localStorage`, функции `loadHistory`/`renderHistory`/`rememberLink` и вызов `rememberLink` при старте скачивания. Go-код и API приложения её не знают.

Ограничения:

- `tests/statusbar_check.js` исполняет весь inline-скрипт страницы в VM-песочнице без `localStorage`; после удаления истории скрипт должен по-прежнему загружаться и проходить сценарии статусбара.
- Спека `track-download` сейчас требует историю, поэтому change обязан обновить требование, а не только код.
- Другие UX-функции (drag & drop, предпросмотр, кнопка папки) делят с историей один блок кода и должны остаться нетронутыми.

## Goals / Non-Goals

**Goals:**

- Убрать историю ссылок из UI и фронтенд-состояния минимальным диффом.
- Сохранить drag & drop, предпросмотр и кнопку «Открыть папку загрузок» без изменения поведения.
- Обновить спеку, README и changelog согласованно с удалением.

**Non-Goals:**

- Замена истории на «закреплённые ссылки» или компактный popover.
- Очистка уже сохранённого ключа `yamdl.linkHistory` в профиле WebView2.
- Изменения Go-кода, API Wails и формата `.env`.

## Decisions

1. **Удалить историю полностью, а не скрывать.**
   Убираются `datalist`, атрибут `list`, весь JS-блок истории и вызов `rememberLink`. Скрытая или отключённая флагом история продолжила бы требовать поддержки спеки и кода. Альтернатива — оставить `localStorage`-запись, но не показывать список — отклонена: это мёртвый код и лишнее состояние.

2. **Не заменять нативный список кастомным popover.**
   Вариант с кнопкой-часами, читаемыми названиями и очисткой рассматривался, но требует кэшировать превью, поддерживать клавиатуру и новые состояния ради сценария, который почти не возникает. Если появится реальный запрос, это будет отдельный change.

3. **Не чистить старый ключ `localStorage`.**
   Удаление ключа потребовало бы оставить в коде константу и разовый вызов `removeItem` — то есть сохранить часть удаляемой фичи. Ключ `yamdl.linkHistory` остаётся неиспользуемым и невидимым; данные в нём не секретны (только URL скачанных ссылок). Профиль WebView2 можно очистить штатно.

4. **Классификация изменения.**
   По `docs/versioning.md` удаление фичи — это MAJOR-изменение. В changelog пользовательский блок идёт в `**Изменено**` с пометкой `**BREAKING:**`, инженерная деталь — под `### Изменено`. Версия не бампится в этом change: бамп делает релизный скрипт.

## Risks / Trade-offs

- **Пользователь лишается быстрого повтора ссылки** → ссылку можно снова скопировать из Яндекс Музыки; уже скачанные файлы приложение пропускает, потери данных нет.
- **Основная спека разойдётся с кодом до архивации change** → дельта spec обновляет требование; после реализации выполнить archive и `openspec validate --all`.
- **Нет автотеста на отсутствие списка** → проверить статически (`grep` по `linkHistory`/`datalist`) и вручную запуском окна; существующий `tests/statusbar_check.js` прогнать, чтобы убедиться, что скрипт страницы не сломан.
- **Остаётся неиспользуемый ключ в localStorage** → безвреден, задокументирован в design; при желании пользователь очищает профиль WebView2.

## Migration Plan

- Миграция не требуется: удаление не трогает файлы, настройки и токен. Старый ключ истории игнорируется.
- Откат — revert коммита; после отката история снова заработает с прежними записями, если ключ не был очищен.
- Порядок: код → спека (delta) → README → changelog → проверки; архив change — после приёмки.
