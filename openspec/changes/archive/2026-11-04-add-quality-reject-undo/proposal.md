# Proposal

## Why

После проверки FLAC приложение может предложить поисковое совпадение, которое на самом деле является другой записью — например, ремиксом. Сейчас отклонить его можно только неявно: снять галочку и скачать остальные. После такого отказа файл помечается проверенным как lossless и больше не проверяется, а сам отказ нельзя отменить, если пользователь ошибся.

Нужен явный отказ, который запоминается, не выключает мониторинг локального MP3 и может быть отменён.

## What Changes

- В окне найденного у каждого поискового совпадения появляется действие «Не тот трек»: оно убирает кандидата из списка и сохраняет отказ без скачивания.
- Отказы хранятся для локального файла списком, а не одним значением: отклонение второго кандидата не затирает первого. Запись содержит метаданные найденного трека и не истекает автоматически.
- ID-совпадения не отклоняются: Yandex ID из тегов считается идентичностью файла, а не поисковой догадкой.
- После отказа результат проверки для файла сбрасывается, поэтому MP3 остаётся кандидатом: следующая проверка ищет другие версии, а отклонённая больше не предлагается. Если все найденные кандидаты отклонены, повторная проверка назначается не позже чем через 7 дней.
- В настройках, в разделе мониторинга FLAC, появляется список «Отклонённые совпадения»: локальный файл, найденный трек и дата. У каждой записи есть действие «Вернуть», которое снимает отказ и снова делает кандидата доступным без скачивания.
- Журнал `flac-quality.json` переходит на версию 2. Старые записи `declined` мигрируют, чтобы уже сохранённые отказы не потерялись.
- Отклонение и возврат пишутся в лог понятными строками на русском.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `quality-upgrade`: явное отклонение поискового совпадения, хранение набора отказов, сохранение файла в мониторинге и возврат отклонённого кандидата.
- `app-settings`: список отклонённых совпадений и действие «Вернуть» в разделе мониторинга FLAC.

## Impact

- `src/internal/quality/journal.go` — схема v2, список отказов, миграция v1, методы отклонения, возврата, списка и удаления записи проверки.
- `src/internal/quality/checker.go` — фильтрация отклонённых кандидатов, повторная проверка файла после отказа, TTL 7 дней для случая «все кандидаты отклонены».
- `src/internal/quality/found.go` — `Pending` не показывает отклонённое совпадение, но снова показывает возвращённое.
- `src/internal/ui/quality.go`, `src/internal/ui/app.go` — биндинги отклонения и возврата, `Settings.QualityRejected`, события и лог.
- `src/frontend/dist/index.html`, `src/frontend/dist/app.js`, `src/frontend/dist/app.css` — действие «Не тот трек» в окне найденного, список и «Вернуть» в настройках.
- Тесты: `src/internal/quality/*_test.go`, `src/internal/ui/quality_test.go`, `tests/settings_check.js` и новый JS-стенд для окна найденного.
- Документация: `docs/15-flac-monitor.md`, `CHANGELOG.md` в `[Unreleased]`.
- Учесть незавершённые changes `fix-ui-and-flac-upgrade` (те же файлы UI и `quality-upgrade`) и `add-startup-animation`: применять после них или поверх, не ломая их правки.
- Версия проекта в этом change не меняется: бамп выполняется только при релизе.
