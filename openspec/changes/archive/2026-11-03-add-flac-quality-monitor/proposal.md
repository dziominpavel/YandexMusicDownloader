# Proposal

## Why

Коллекция уже содержит треки, скачанные в MP3, потому что lossless тогда был недоступен. Яндекс со временем добавляет FLAC для старых треков, но приложение об этом не узнаёт: повторная вставка ссылки пропускает файл как «already exists», а вручную проверять сотни MP3 неудобно.

Проверка уже почти реализована: тот же `get-file-info?quality=lossless`, который использует скачивание, отвечает кодеком без загрузки аудио. Не хватает мониторинга коллекции, сопоставления файлов с треками Яндекса и безопасного обновления на месте.

## What Changes

- Новый параметр `.env` `FLAC_MONITOR` (по умолчанию выключен): автоматическая проверка коллекции при запуске (не чаще раза в 7 дней) и раз в 7 дней, пока окно открыто. Кнопка «Проверить сейчас» работает всегда.
- Кандидаты — только `.mp3` из `LIBRARY_DIR` и `OUTPUT_DIR`; `.flac` уже lossless, `.m4a` в v1 не рассматривается (отдельный случай ALAC/AAC).
- Сопоставление: сначала Yandex ID из тегов (`YANDEX_TRACK_ID`/UFID/source-url); если ID нет — поиск по исполнителю и названию через `/search` с нечётким сравнением и обязательным подтверждением пользователя.
- Проверка lossless через `get-file-info` с троттлингом и журналом: «FLAC нет» перепроверяется реже, ошибки/недоступность — по своим TTL; при смене аккаунта или появлении Плюса журнал сбрасывается. Ответ `smart_preview`/`preview` и 403 останавливают проверку, а не помечают все треки как «FLAC нет».
- При находке — окно со сводкой и списком: локальный файл, текущий формат, найденный формат, для поисковых совпадений — найденный трек, альбом, год и процент. ID-совпадения предвыбраны, поисковые — только при уверенном совпадении. Действия: «Скачать все», «Показать список», «Позже».
- Подтверждённое обновление идёт обычной job'ой с прогрессом и «Остановить»: lossless во временный файл → ALAC→FLAC при `flac-mp4` → теги → атомарная публикация `.flac` (или lossless `.m4a`, если ffmpeg нет) рядом со старым файлом → старый файл в `<корень>\_old\<относительный путь>`.
- Если lossless внезапно пропал и пришёл MP3-fallback, старый файл MUST NOT перемещаться; причина пишется в лог.
- `_old` игнорируется индексом коллекции и проверкой дублей; при занятом имени в `_old` добавляется метка времени.
- Новые настройки в окне: чекбокс автоматической проверки, кнопка «Проверить сейчас», дата и время последней проверки и её результат (найдено N / ничего не найдено / ошибка); то же компактно видно рядом с кнопкой проверки в главном окне. `FLAC_MONITOR` применяется без перезапуска.
- Ограничение: при закрытом приложении проверок нет — это десктопное приложение, а не служба.

## Capabilities

### New Capabilities

- `quality-upgrade`: мониторинг не-lossless файлов коллекции, сопоставление с треками Яндекса по ID или исполнителю/названию, проверка доступности lossless, журнал проверок, окно предложения и обновление файла на месте с перемещением старого в `_old`.

### Modified Capabilities

- `library-index`: в записи индекса добавляются Yandex ID и source URL; `_old` исключается из обхода; при включённом мониторинге индекс строится по `OUTPUT_DIR` даже без `LIBRARY_DIR`, но проверка дублей остаётся выключенной.
- `app-settings`: новые параметры мониторинга, их горячее применение и отображение состояния проверки.
- `desktop-app`: кнопка проверки/бейдж найденного, окно сводки и списка, участие фоновой job'ы в состояниях «Скачать/Остановить» и статусбаре.

## Impact

- Код: `src/internal/config` (новый параметр), `src/internal/library` (ID/source-url, `_old`, снимок записей), `src/internal/downloader` (probe lossless, поиск, кэш UID, скачивание в явный путь), новый пакет `src/internal/quality` (кандидаты, журнал, сопоставление, оркестрация), `src/internal/ui/app.go` (триггеры, окно, job'а), `src/frontend/dist/index.html` (кнопка, модалка, настройки).
- Конфигурация: `.env.example`, `docs/` (описание `FLAC_MONITOR` и `_old`).
- Спеки: новая `openspec/specs/quality-upgrade/spec.md`; дельты `library-index`, `app-settings`, `desktop-app`.
- Существующее поведение скачивания (`[skip] already exists`, fallback MP3, теги, атомарность) сохраняется; обновление использует тот же пайплайн, а не заменяет его.
- Первый прогон на текущей коллекции: 67 MP3 из `downloads` готовы к lossless (`flac-mp4`), 10 файлов с ID в `F:` пока отдают только `aac-mp4`, часть из 92 внешних MP3 может найтись поиском.
