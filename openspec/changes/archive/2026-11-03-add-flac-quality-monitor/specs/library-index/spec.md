# Spec Delta

## MODIFIED Requirements

### Requirement: Конфигурация через LIBRARY_DIR

Приложение MUST читать параметр `LIBRARY_DIR` из `.env`; параметр MUST также быть настраиваемым из окна настроек (см. capability `app-settings`) с горячим применением без перезапуска. Если параметр отсутствует или пуст — индексация коллекции и проверка дублей MUST быть выключены полностью (ни сканирования, ни диалогов, ни строк `[index]` в логе). Если включён `FLAC_MONITOR` (см. capability `quality-upgrade`), приложение MUST индексировать `OUTPUT_DIR` и без `LIBRARY_DIR`, но проверка дублей MUST оставаться выключенной. Если путь указан, но не существует, приложение MUST сообщить об этом в логе на русском и продолжить работу без проверки дублей.

#### Scenario: Параметр задан

- **WHEN** в `.env` задан `LIBRARY_DIR=D:\Music` и путь существует
- **THEN** при запуске приложение индексирует указанную папку и проверяет ссылки перед скачиванием

#### Scenario: Параметр не задан

- **WHEN** `LIBRARY_DIR` отсутствует в `.env` или пуст, а `FLAC_MONITOR` выключен
- **THEN** приложение работает ровно как раньше: без индексации, без строк `[index]` и без диалогов о дублях

#### Scenario: Мониторинг без LIBRARY_DIR

- **WHEN** `LIBRARY_DIR` пуст, а `FLAC_MONITOR` включён
- **THEN** приложение индексирует `OUTPUT_DIR` для мониторинга, но диалоги о дублях и проверка перед скачиванием остаются выключенными

#### Scenario: Путь не существует

- **WHEN** `LIBRARY_DIR` указывает на несуществующую папку
- **THEN** в логе появляется сообщение об ошибке пути на русском, приложение продолжает работать без проверки дублей

#### Scenario: Путь изменён в настройках

- **WHEN** пользователь указал новый `LIBRARY_DIR` в окне настроек и сохранил
- **THEN** без перезапуска запускается индексация новой папки (в фоне, с прогрессом в логе), проверка дублей работает по новому пути

#### Scenario: Путь очищен в настройках

- **WHEN** пользователь сохранил настройки с пустым `LIBRARY_DIR`, а `FLAC_MONITOR` выключен
- **THEN** индексация и диалоги о дублях выключаются до тех пор, пока путь не задан снова

## ADDED Requirements

### Requirement: Yandex ID и source URL в индексе

Для каждого аудиофайла индекс MUST сохранять Yandex ID и source URL, извлекая их из `YANDEX_TRACK_ID` (FLAC), UFID или COMM (MP3), source-url (M4A) либо разбирая URL. Отсутствие ID MUST NOT исключать файл из индекса и проверки дублей; файл без ID MAY участвовать в мониторинге через поиск по исполнителю и названию.

#### Scenario: FLAC с YANDEX_TRACK_ID

- **WHEN** в FLAC есть Vorbis comment `YANDEX_TRACK_ID`
- **THEN** индекс сохраняет этот ID и source URL из `COMMENT`

#### Scenario: MP3 с source-url

- **WHEN** в MP3 есть COMM с описанием `yandex-music-downloader:source-url`
- **THEN** индекс извлекает ID трека из URL

#### Scenario: Внешний файл без ID

- **WHEN** у MP3 нет ни Yandex ID, ни source URL, но есть исполнитель и название
- **THEN** файл остаётся в индексе для проверки дублей и может участвовать в мониторинге через поиск по названию

### Requirement: Исключение _old из индекса

Каталог `_old` в корне `LIBRARY_DIR` или `OUTPUT_DIR` и любые вложенные `_old` MUST исключаться из обхода. Файлы в нём MUST NOT участвовать в проверке дублей и мониторинге качества; их изменение MUST NOT влиять на индекс.

#### Scenario: Старый MP3 не считается дублем

- **WHEN** обновлённый трек лежит в `_old`, а пользователь снова скачивает этот же трек
- **THEN** файл из `_old` не вызывает предупреждение о дубле

#### Scenario: Файл вернули из _old

- **WHEN** пользователь переместил файл из `_old` обратно в коллекцию
- **THEN** следующее обновление индекса снова видит его как обычный аудиофайл
