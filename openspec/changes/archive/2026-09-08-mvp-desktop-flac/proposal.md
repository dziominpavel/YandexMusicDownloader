## Why

Проект находится на стадии «доки и спеки, кода нет». Чтобы проверить выбранный стек (Go + Windows-окно + один exe) на практике, нужен минимальный сквозной результат: окно, в которое вставляют ссылку, и настоящий `.flac` с тегами на диске. Это разблокирует все дальнейшие фичи (альбомы, плейлисты, инструкция для друзей).

## What Changes

- Go-модуль и каркас `src/`: `config` (чтение `.env`), `resolver` (парсинг ссылки на трек), `downloader` (lossless → fallback MP3, потоковая запись, `temp → rename`), `tagger` (обязательные теги + обложка)
- Десктопное Windows-окно: поле для ссылки, кнопка «Скачать», строковый лог (`[downloading]/[done]/[fallback]/[skip]/[error]`)
- Протокол скачивания и подписи портируются из `references/01-stmol-yandex-music-downloader`, теговая схема — из `docs/03-repo-nnikitochka.md`
- Сборка в один `app.exe` (`go build`), черновик инструкции по токену для друзей
- Альбомы/плейлисты/чарты, жанры с переводом, `.lrc` — НЕ входят (это v0.2)

## Capabilities

### New Capabilities

- `desktop-app`: окно приложения (поле + кнопка + лог) и поставка одним exe-файлом без консоли и зависимостей

### Modified Capabilities

- Нет. Поведение `track-download` и `audio-tagging` реализуется как описано в основных спеках, требования не меняются.

## Impact

- Новый код: `src/` (Go), сборка `app.exe`
- Зависимости: GUI-фреймворк (Wails v2 дефолт, Fyne запасной — финал в `design.md`), теговые библиотеки (`go-flac`, `id3v2`, `mtag` — как у Stmol)
- Не затрагивает: `docs/` (кроме `10-roadmap.md` по факту), `references/` (только чтение)
