# 15. Мониторинг качества FLAC

Приложение умеет следить за уже скачанными MP3 и предлагать обновить их,
если на Яндекс Музыке появился lossless-вариант. Это не отдельная служба:
проверка работает только пока открыто окно приложения.

## Включение

В `.env` рядом с exe:

```dotenv
FLAC_MONITOR=true
```

По умолчанию параметр выключен. Его же можно включить чекбоксом
«Проверять наличие FLAC автоматически» в окне «Настройки». Изменение
применяется без перезапуска.

## Что проверяется

- Только `.mp3` из `LIBRARY_DIR` (папка коллекции) и `OUTPUT_DIR`
  (папка загрузок), включая подкаталоги.
- Файлы `.flac` уже lossless и пропускаются; `.m4a` в v1 не проверяется.
- Сначала используется Yandex ID из тегов (`YANDEX_TRACK_ID`, UFID или
  source-url). Если ID нет, приложение ищет трек по исполнителю и
  названию через поиск Яндекса и показывает найденного кандидата с
  альбомом, годом и процентом совпадения. Поисковое совпадение скачивается
  только после подтверждения.

## Когда проверяется

- При запуске, если с последней успешной проверки прошло не меньше
  7 дней, и затем раз в 7 дней, пока окно открыто.
- Всегда доступна кнопка «Проверить сейчас» в разделе «Мониторинг FLAC»
  окна настроек.
- При закрытом приложении проверок нет; при следующем запуске
  расписание догоняется.

## Что видно

В разделе «Мониторинг FLAC» окна настроек — строка результата:

```
FLAC: 03.11.2026 18:00 — найдено 67
FLAC: 03.11.2026 18:00 — ничего не найдено
FLAC: 03.11.2026 18:00 — ошибка
FLAC: проверок не было
```

Она обновляется после каждой проверки, даже если ничего не найдено.
Количество найденных обновлений показывается бейджем на кнопке
«Настройки» в главном окне. Автопроверка не открывает окно сама: бейдж
и строка в настройках дают сигнал, а окно открывается кнопкой
«Открыть найденное (N)».

Окно найденного показывает локальный файл, `MP3 → FLAC`, папку
назначения нового FLAC (`OUTPUT_DIR`) и правило `_old`; для поисковых
совпадений — найденный трек, альбом, год и процент. Кнопки: «Скачать все»,
«Показать список», «Позже». «Позже» сохраняет список и бейдж.

## Отклонение ложного совпадения

У поискового совпадения в окне найденного есть кнопка «Не тот трек». Она
убирает кандидата из списка и запоминает отказ: файл не скачивается, MP3
остаётся на месте. Отклонённый кандидат больше не предлагается для этого
файла, но сам MP3 остаётся в мониторинге: следующая проверка ищет другие
версии. Если отклонены все найденные кандидаты, повторная проверка
назначается не позже чем через 7 дней.

В разделе «Мониторинг FLAC» есть список «Отклонённые совпадения»: локальный
файл, найденный трек и дата. Кнопка «Вернуть» снимает отказ и снова делает
кандидата доступным; скачивание при этом не запускается. Отказы не истекают
сами и хранятся до возврата.

ID-совпадения не отклоняются: Yandex ID из тегов считается идентичностью
файла. Если ID неверный, это отдельная задача про теги, а не про поиск.

## Что происходит при обновлении

1. Lossless скачивается во временный файл в `OUTPUT_DIR`.
2. Если сервер отдал `flac-mp4` (ALAC), при наличии `ffmpeg.exe` и
   `CONVERT_M4A=true` аудио перегоняется в plain FLAC; иначе сохраняется
   lossless `.m4a`.
3. Файл получает теги и публикуется атомарно в `OUTPUT_DIR` с обычным
   именем `Исполнитель - Название.ext` (с учётом `SUBDIRS`). Новый
   аудиофайл в `LIBRARY_DIR` не пишется.
4. Только после успешной публикации старый MP3 перемещается в
   `<корень старого файла>\_old\<относительный путь>`, его `.lrc` — вместе
   с ним.
5. Если вместо lossless пришёл MP3-fallback или публикация не удалась,
   старый файл остаётся на месте.

Для MP3 из коллекции это значит: новый FLAC лежит в папке загрузок, а
старый MP3 — в `LIBRARY_DIR\_old`. В самой коллекции трека не остаётся;
перенести FLAC туда можно вручную.

`_old` игнорируется индексом коллекции и проверкой дублей. Если имя в
`_old` занято, добавляется метка времени. Чистка `_old` — вручную.

## Ограничения

- Нет проверок при закрытом приложении: это десктопное приложение, а не
  служба.
- Нет автоматического скачивания без подтверждения: найденное всегда
  показывается пользователю.
- Без активной подписки Плюс lossless недоступен; проверка сообщает об
  этом и не помечает треки как «FLAC нет».
- Если токен истёк или Яндекс отвечает `smart_preview`, проверка
  останавливается, а журнал не портится. Одиночный 403 по треку означает,
  что трек недоступен; серия из трёх 403 подряд останавливает проверку.
- Файлы без Yandex ID и без пригодных исполнителя/названия пропускаются.
- Уже существующие FLAC не перепроверяются на целостность.

## Журнал

Рядом с `library-index.json` лежит `flac-quality.json`. Он хранит статусы
проверок, время последней попытки/успеха, результат и отклонённые
совпадения, чтобы не дёргать API каждый запуск. «FLAC нет» перепроверяется
не чаще раза в 30 дней, ошибки — по короткому TTL, недоступные треки — по
длинному. При смене аккаунта или появлении Плюса журнал сбрасывается.

Отклонённые совпадения хранятся в журнале версии 2 списком на локальный
файл и не имеют автоматического срока. При загрузке старый журнал версии 1
мигрирует: активные отказы сохраняются, просроченные — отбрасываются. Файл
можно удалить — он создастся заново, но отклонения при этом потеряются. При
откате на старую версию приложения журнал версии 2 будет проигнорирован и
пересобран, поэтому отказы тоже исчезнут.
