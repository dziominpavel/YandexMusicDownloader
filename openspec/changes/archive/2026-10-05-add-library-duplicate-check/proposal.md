## Why

Один и тот же трек может попасть в коллекцию дважды: имя файла на диске отличается от того, что придёт от API (два исполнителя указаны в разном порядке, другая версия, кавер, другой формат). Сейчас программа ловит только точное совпадение имени файла и повтор ID внутри плейлиста, поэтому «тихие» дубли проходят без предупреждения.

## What Changes

- Новый параметр `.env` `LIBRARY_DIR` — путь к папке музыкальной коллекции пользователя. Пусто/отсутствует — фича выключена.
- Индексация коллекции: рекурсивный обход `LIBRARY_DIR` (включая подкаталоги) и автоматически `OUTPUT_DIR`, чтение тегов (исполнитель, заголовок, расширение) с фолбэком на имя файла, нормализация и поиск кандидатов по схожести (~90–95%), а не по точному равенству.
- Кэш индекса файлом рядом с exe + инкрементальное обновление по size/mtime. Первое сканирование идёт в фоне с информированием в логе; проверка во время индексации честно помечается как неполная.
- Перед скачиванием трека — проверка индекса: при совпадении выше порога диалог подтверждения «возможен дубль» (с процентом совпадения, путём найденного файла и учётом разного формата). Пользователь подтверждает или отказывается.
- Для плейлиста подтверждение запрашивается на каждый трек отдельно.
- ID Яндекса в тегах для проверки не используется — коллекция может содержать файлы из любых источников.

## Capabilities

### New Capabilities

- `library-index`: индексация музыкальной коллекции (обход подкаталогов, чтение тегов, кэш и инкремент, нормализация имён с учётом правила сортировки кириллицы, поиск кандидатов по схожести) и его конфигурация через `LIBRARY_DIR`.

### Modified Capabilities

- `track-download`: новая обязанность — проверять индекс на возможный дубль перед стартом скачивания каждого трека и запрашивать подтверждение пользователя; без `LIBRARY_DIR` проверка не выполняется.

## Impact

- Код: `src/internal/config` (новый параметр), новый пакет-индексатор (например `src/internal/library`), `src/internal/ui/app.go` (проверка перед `Download`/`DownloadPlaylist` + диалог подтверждения), фронтенд `src/frontend/dist/index.html` (если диалог делается на стороне UI — либо нативный диалог Wails, решение в design).
- Зависимости: чтение тегов — существующие парсеры проекта (ID3v2/Vorbis/MP4) или их обёртка; схожесть строк — своя реализация или минимальная зависимость.
- Конфигурация: `.env.example`, `docs/` (описание `LIBRARY_DIR`).
- Спеки: `openspec/specs/track-download/spec.md` (дельта), новая `openspec/specs/library-index/spec.md`.
- Существующее поведение (`[skip] already exists`, дедупликация по ID в плейлисте) сохраняется — новая проверка дополняет, а не заменяет его.
