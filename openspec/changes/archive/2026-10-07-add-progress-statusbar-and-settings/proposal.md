## Why

Пользователь не видит общей картинки скачивания: для одиночного трека прогресса нет вообще (событие передаётся `nil`), а для плейлиста нет агрегированного «насколько скачался в итоге» — только локальные полоски у строк. Вторая боль — все настройки спрятаны в `.env`, который надо править руками в блокноте: токен, пути, воркеры недоступны из окна, часть ключей (`SKIP_COVER`, `FORMAT`) вообще не читаются кодом.

## What Changes

**Фича 1 — агрегированный статусбар прогресса:**

- Новая полоса на всю ширину окна между строкой ввода и списком треков/логом: общий процент job'ы, счётчик треков (`12/20`), сумма байтов при известных размерах.
- Общий `% = (завершённые + сумма долей активных) / N` — знаменатель стабилен с старта, не прыгает, работает при неизвестном размере файла.
- Одиночный трек становится job'ой из 1: получает события `track-status`/`progress` (сейчас их нет — `DownloadTrack` вызывается с `onProgress=nil`), его прогресс виден и в статусбаре.
- Существующие per-track строки плейлиста сохраняются как есть.

**Фича 2 — окно настроек:**

- Кнопка «Настройки» в окне открывает форму с параметрами: `YANDEX_TOKEN` (с проверкой через `account/status`), `OUTPUT_DIR`, `LIBRARY_DIR` (с выбором папки), `PLAYLIST_WORKERS` (1..10), `CONVERT_M4A`, `EMBED_COVER`.
- Настройки хранятся в том же `.env` рядом с exe: окно редактирует этот файл (сохраняя комментарии и незнакомые ключи), один источник правды, ручные правки `.env` не конфликтуют.
- После «Сохранить» — горячее применение без перезапуска: перевалидация токена, пересоздание клиента, пересборка индекса библиотеки.
- Подключается ключ обложки: `EMBED_COVER` (дефолт `true`, чекбокс «Встраивать обложку») читается из `.env` и передаётся в тегер (сейчас хардкод — обложка всегда встраивается); мёртвый `FORMAT` убирается из `.env.example` (FLAC-first захардкожен спекой, реализовывать нечего).
- На время скачивания окно настроек недоступно.

**Фича 3 — остановка активной загрузки:**

- Пока идёт job'а, кнопка «Скачать» не блокируется, а превращается в красную «■ Остановить» (потом «Останавливаю…») — одна кнопка, место в строке не меняется.
- Остановка обрывает активную передачу (контекст job'ы в запросах) и не даёт пулу запустить очередные треки: не начатые получают статус `[stopped]`, а не `[error]`, временные файлы недокачанных треков удаляются.
- Итог остановки — `[stopped] прервано: ...` вместо `[finished]`, статусбар замораживается на фактическом проценте (не тянется до 100%) с пометкой «остановлено».
- После остановки приложение полностью готово к следующей загрузке без перезапуска.

## Capabilities

### New Capabilities

- `app-settings`: окно настроек — состав полей, редактирование `.env`, горячее применение, недоступность во время скачивания.

### Modified Capabilities

- `track-download`: новое требование об агрегированном статусбаре прогресса (включая одиночный трек как job'у из 1); уточняется требование «Токен из окружения» — токен можно задать и проверить в окне настроек.
- `desktop-app`: требование «Окно с полем, кнопкой и логом» дополняется кнопкой «Настройки»; добавляется требование «Кнопка остановки активной загрузки»; токен по-прежнему MUST читаться из `.env`, но путь «правка руками» дополняется «правка из окна настроек».
- `audio-tagging`: требование «Обложка» — `EMBED_COVER` задаётся не только через `.env`, но и из окна настроек, применяется без перезапуска.
- `library-index`: требование «Конфигурация через LIBRARY_DIR» — путь можно менять в окне настроек, изменение применяется без перезапуска (пересборка индекса).

## Impact

- `src/frontend/dist/index.html` — новый статусбар + агрегация, кнопка/модалка настроек, режим «■ Остановить».
- `src/internal/ui/app.go` — прогресс и статусы для одиночного трека, жизненный цикл job'ы, биндинги настроек, хот-релоад, биндинг `Stop`.
- `src/internal/downloader/stop.go`, `track.go`, `batch.go`, `lossless.go`, `mp3.go` — контекст job'ы, обрыв по остановке, счётчик `Summary.Stopped`.
- `src/internal/config/config.go` — чтение `EMBED_COVER`, writer `.env` (правка значений с сохранением комментариев).
- `src/internal/tagger` — `Adapter(cfg.EmbedCover)` вместо хардкода.
- `.env.example` — убрать мёртвый `FORMAT`, документировать поведение `EMBED_COVER`.
- Спеки: `track-download`, `desktop-app`, `audio-tagging`, `library-index` (дельты), новая `app-settings`.
- Тесты: `config_test`, `app_test`, `app_stop_test`, `stop_test`, фронтенд-логика агрегации.
