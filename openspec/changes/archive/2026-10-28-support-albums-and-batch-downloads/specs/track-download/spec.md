# Spec Delta

## MODIFIED Requirements

### Requirement: Скачивание трека по ссылке

Приложение MUST принимать ссылку вида `music.yandex.ru/album/{albumId}/track/{trackId}`, ссылку вида `music.yandex.(ru|com|kz|by|uz)/album/{albumId}` (без trackId), ссылку вида `music.yandex.(ru|com|kz|by|uz)/playlists/{uuid}` (включая префиксы вида `lk.<uuid>`, `ps.<uuid>` и query-хвосты), а также несколько ссылок в одном вводе (разделённые переносом строки, пробелом или запятой). Приложение MUST скачивать аудио в `OUTPUT_DIR` (по умолчанию `./downloads`).

#### Scenario: Вставил ссылку — получил файл

- **WHEN** пользователь вставляет ссылку на трек и нажимает «Скачать»
- **THEN** в логе появляется `[downloading] Artist — Title`, а после завершения — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Файл уже есть

- **WHEN** целевой файл уже существует в папке назначения
- **THEN** скачивание пропускается и в логе появляется `[skip] Artist — Title (already exists)`

#### Scenario: Вставил ссылку на плейлист — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.by/playlists/{uuid}` и нажимает «Скачать»
- **THEN** появляется заголовок `[playlist] Название (N треков)` и ровно по одной строке на каждый уникальный трек (в порядке плейлиста, со статусом `[queued]`), а в конце — `[finished] X ok, Y skip, Z error`

#### Scenario: Вставил ссылку на альбом — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.ru/album/{albumId}` и нажимает «Скачать»
- **THEN** приложение резолвит альбом в список треков и скачивает их тем же способом, что и плейлист: заголовок `[album] Название (N треков)`, по одной строке на каждый трек, общий прогресс, итоговая строка `[finished] X ok, Y skip, Z error`

#### Scenario: Одна строка на трек

- **WHEN** трек плейлиста или альбома качается и завершается
- **THEN** его строка обновляется на месте (`[queued]` → `[downloading]` → `[done] (FLAC|MP3)` с цветом), новые строки на каждое событие НЕ добавляются; строка пропуска показывает `[skip] (already exists|duplicate|unavailable)`, строка ошибки — `[error]` с причиной

#### Scenario: Плейлист с query-хвостом и префиксом

- **WHEN** ссылка имеет вид `music.yandex.ru/playlists/lk.<uuid>?utm_source=web`
- **THEN** приложение принимает ее как плейлист и резолвит тот же набор треков, что и без префикса и хвоста

#### Scenario: Несколько ссылок разом

- **WHEN** пользователь вставляет в поле ввода несколько ссылок (разделённые переносом строки, пробелом или запятой), нажимает «Скачать»
- **THEN** приложение обрабатывает каждую ссылку по очереди, применяя соответствующий пайплайн для каждого (альбом/плейлист/трек). Если одна из ссылок некорректна — она пропускается с `[error]`, остальные обрабатываются дальше.

### Requirement: Пакетное скачивание плейлиста

Приложение MUST скачивать треки плейлиста и альбома пулом параллельных воркеров с настраиваемым числом (`PLAYLIST_WORKERS` в `.env`: целое 1..10, по умолчанию 3), при этом каждый трек MUST проходить стандартный пайплайн (FLAC first с MP3-fallback, обязательные теги, потоковая запись, атомарная публикация `temp → rename`). Ошибка или недоступность одного трека MUST NOT останавливать остальные. Повтор одного и того же ID внутри плейлиста/альбома MUST скачиваться один раз, повторные вхождения пропускаются как уже обработанные.

#### Scenario: Пачка из нескольких треков

- **WHEN** плейлист или альбом содержит 5 уникальных доступных треков
- **THEN** все 5 файлов появляются в `downloads/` с тегами, 5 строк треков переходят в `[done]`, а финал — `[finished] 5 ok, 0 skip, 0 error`

#### Scenario: Недоступный трек пропускается

- **WHEN** трек плейлиста или альбома недоступен (`available=false`, нет прав, 403/404)
- **THEN** строка трека показывает `[skip] (unavailable)`, остальные треки качаются дальше, счетчик `skip` в финале увеличивается

#### Scenario: Дубль качается один раз

- **WHEN** один и тот же ID встречается в плейлисте или альбоме дважды
- **THEN** файл скачивается один раз, строка трека показывает `[skip] (duplicate)`, повторной записи файла нет

#### Scenario: Ошибка одного не роняет пачку

- **WHEN** один трек завершается ошибкой сети или тегирования
- **THEN** строка трека показывает `[error]` с причиной, остальные треки продолжают качаться, финал учитывает ошибку в счетчике `error`

#### Scenario: Число воркеров настраивается

- **WHEN** в `.env` задано `PLAYLIST_WORKERS=10`
- **THEN** до 10 треков качаются параллельно

#### Scenario: Мусор в настройке воркеров

- **WHEN** `PLAYLIST_WORKERS` отсутствует, не число или вне диапазона 1..10
- **THEN** приложение использует значение по умолчанию 3 и работает как обычно

## ADDED Requirements

### Requirement: Сетевые ретраи

Приложение MUST автоматически повторять временные сетевые ошибки (ошибки соединения, таймауты, временные сетевые сбои) при получении метаданных и скачивании файла. Количество попыток MUST быть небольшим (не более 3), с минимальным бэкоффом между попытками. Ретраи MUST применяться только к сетевым/транзиентным ошибкам; бизнес-ошибки (недоступность трека, 403/404 по правам, ошибки резолва) MUST НЕ ретраиться. При исчерпании попыток трек MUST помечаться как `[error]` с понятной причиной.

#### Scenario: Временный таймаут при скачивании

- **WHEN** при скачивании трека возникает сетевой таймаут
- **THEN** приложение делает до 3 попыток с небольшим бэкоффом, и только после исчерпания попыток показывает `[error]` с причиной

#### Scenario: Недоступность трека не ретраится

- **WHEN** трек недоступен (`available=false` или ответ 403/404 по правам)
- **THEN** ретраев не происходит, трек сразу помечается как `[skip] (unavailable)` или `[error]` без повторных попыток

#### Scenario: Ретраи не влияют на плейлист

- **WHEN** один трек в плейлисте/альбоме получает сетевой сбой и после ретраев заканчивается ошибкой
- **THEN** остальные треки плейлиста/альбома продолжают скачиваться, счётчик ошибок корректно учитывается в итоговой строке `[finished]`
