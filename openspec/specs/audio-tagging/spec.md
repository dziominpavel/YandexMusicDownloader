## Purpose

Каждый скачанный файл MUST содержать корректные теги и обложку: коллекция должна быть пригодна для плеера без ручной правки. Это закрывает главную боль референса Stmol.

## Requirements

### Requirement: Обязательные теги

Приложение MUST записывать в каждый файл: название, исполнителя(ей), альбом, год, номер трека и всего треков, жанр, идентификатор трека (`YM_ID`), обложку. Теги пишутся до публикации файла.

#### Scenario: Проверка тегов FLAC

- **WHEN** скачивание FLAC завершено
- **THEN** в файле есть `TITLE`, `ARTIST`, `ALBUM`, `DATE`, `TRACKNUMBER`, `TRACKTOTAL`, `GENRE`, обложка

### Requirement: Мультиартист

При нескольких исполнителях приложение MUST записывать каждого отдельным полем, а не одной строкой через запятую.

#### Scenario: Фит двух артистов

- **WHEN** у трека два исполнителя
- **THEN** плеер показывает обоих как отдельных артистов (навигация по каждому работает)

### Requirement: Обложка

Приложение MUST встраивать обложку в тег файла. Отдельное сохранение `cover.jpg` рядом — опционально. Флаг `EMBED_COVER=false` MUST отключать только обложку, текстовые теги при этом пишутся как обычно; дефолт флага — встраивать обложку, невалидное значение `EMBED_COVER` MUST игнорироваться (флаг остаётся включённым). Флаг MUST читаться из `.env` и MUST быть настраиваемым из окна настроек (см. capability `app-settings`); изменение применяется для следующих скачиваемых файлов без перезапуска. Ключ `SKIP_COVER` MUST не читаться.

#### Scenario: Обложка по умолчанию

- **WHEN** в `.env` ключ `EMBED_COVER` отсутствует и скачан трек
- **THEN** файл содержит все текстовые теги и встроенную картинку

#### Scenario: Пропуск обложки

- **WHEN** задан `EMBED_COVER=false`
- **THEN** файл содержит все текстовые теги, но без встроенной картинки

#### Scenario: Невалидное значение игнорируется

- **WHEN** задан `EMBED_COVER=maybe`
- **THEN** обложка встраивается — значение проигнорировано, флаг остался включённым

#### Scenario: Выключено в окне настроек

- **WHEN** пользователь выключил чекбокс «Встраивать обложку (текстовые теги пишутся)» в окне настроек и сохранил, затем скачал трек
- **THEN** новый файл без обложки, текстовые теги на месте, перезапуск не требуется

#### Scenario: Старый ключ не действует

- **WHEN** в `.env` остался только `SKIP_COVER=true`, ключа `EMBED_COVER` нет
- **THEN** обложка встраивается — старый ключ проигнорирован

#### Scenario: Обложка включена обратно

- **WHEN** пользователь снова включил чекбокс «Встраивать обложку» в окне настроек и скачал трек
- **THEN** в новый файл обложка встроена как обычно

### Requirement: Имена файлов

Имя файла MUST собираться по плоскому шаблону `%artist% - %title%.%ext%` без подпапок (все файлы лежат прямо в папке загрузок), где `%ext%` — реальный контейнер (`flac`, `m4a`, `mp3`). Преобразование первого символа имени исполнителя MUST применяться только к русским: если ни в имени исполнителя, ни в названии трека нет кириллицы, имя MUST оставаться нетронутым (`Metallica`, не `Мetallica`). Первый символ имени исполнителя MUST преобразовываться по правилу сортировки (кириллица — как есть, латиница-двойник — в кириллицу, иначе префикс `ι ` (йота U+03B9 + пробел)), запрещённые для файловой системы символы MUST заменяться на `_`. Детали и таблица двойников — `docs/12-file-naming.md`.

#### Scenario: Плоская раскладка с правилом сортировки

- **WHEN** скачиваются треки `Mari Sa — Моя Любовь` (M4A), `Noize MC — Светлая полоса` (FLAC) и `Амирчик — Не верю` (FLAC)
- **THEN** в папке загрузок лежат ровно три файла без подпапок: `Мari Sa - Моя Любовь.m4a`, `ιNoize MC - Светлая полоса.flac`, `Амирчик - Не верю.flac`

#### Scenario: Иностранец не трогается

- **WHEN** скачивается трек `Metallica — Enter Sandman` (MP3)
- **THEN** файл называется `Metallica - Enter Sandman.mp3` — первый символ НЕ заменяется на кириллицу

### Requirement: Текст песни в тегах

Приложение MUST по умолчанию встраивать текст песни в тег файла, если он доступен в API Яндекс.Музыки. Для FLAC MUST использоваться Vorbis comment `LYRICS`, для MP3 — `USLT`, для M4A — тег `©lyr`. Если текста нет — приложение MUST пропускать без ошибки. Поведение MUST настраиваться в окне настроек: `EMBED_LYRICS` (по умолчанию `true`, вшивать текст). Если `EMBED_LYRICS=false`, текст в тег не встраивается.

#### Scenario: Лирика вшита по умолчанию

- **WHEN** у трека есть текст песни в API и `EMBED_LYRICS` не задан или `true`
- **THEN** в файле появляется текст в соответствующем теге (`LYRICS`/`USLT`/`©lyr`), файл публикуется как обычно

#### Scenario: Лирики нет

- **WHEN** у трека нет текста в API
- **THEN** тег с текстом не добавляется, скачивание не завершается ошибкой

#### Scenario: Встраивание выключено

- **WHEN** `EMBED_LYRICS=false` в настройках
- **THEN** текст песни не встраивается в тег, остальные теги пишутся как обычно

### Requirement: Синхронизированная лирика рядом с файлом

Приложение MUST иметь настройку `SAVE_LRC` (по умолчанию `false`). Если `SAVE_LRC=true` и у трека есть синхронизированная лирика с таймингами, приложение MUST сохранить её в файл рядом с аудиофайлом с тем же базовым именем и расширением `.lrc`. Если лирика несинхронизированная или отсутствует — приложение MUST пропускать без ошибки.

#### Scenario: Сохранение .lrc при включённой настройке

- **WHEN** у трека есть синхронизированная лирика и `SAVE_LRC=true`
- **THEN** рядом с аудиофайлом создаётся `.lrc` файл с тем же базовым именем

#### Scenario: .lrc не сохраняется по умолчанию

- **WHEN** `SAVE_LRC` не задан или `false`
- **THEN** `.lrc` файл не создаётся
