## Purpose

Диагностический файловый лог: сохраняет строки, которые приложение показывает в окне, чтобы сбой можно было разобрать после закрытия окна.

## Requirements

### Requirement: Файл лога рядом с приложением

Приложение MUST вести файл `app.log` в папке с `app.exe` и MUST дописывать новые записи в конец, не очищая файл при запуске.

#### Scenario: Первый запуск

- **WHEN** приложение запущено и файла `app.log` ещё нет
- **THEN** рядом с `app.exe` создаётся `app.log` с записями текущего запуска

#### Scenario: Повторный запуск

- **WHEN** приложение запущено повторно при наличии `app.log`
- **THEN** прежние записи сохраняются, новые дописываются в конец

### Requirement: Формат записи

Каждая запись MUST начинаться с локального времени в формате RFC 3339, уровня в квадратных скобках и текста сообщения: `2026-10-30T12:34:56+03:00 [error] текст`. Переводы строк внутри сообщения MUST сохраняться без изменений.

#### Scenario: Обычная запись

- **WHEN** в лог попадает сообщение `[done] Artist — Title (FLAC)`
- **THEN** в файле появляется строка с временем, уровнем `[done]` и этим текстом

#### Scenario: Многострочная ошибка

- **WHEN** сообщение об ошибке содержит переводы строк
- **THEN** в файле сохраняются все строки сообщения после строки с временем и уровнем

### Requirement: Шапка запуска

При старте приложение MUST записывать в файл версию сборки (или VCS-ревизию), ОС и архитектуру, путь к `app.exe`, путь к `.env`, папку загрузок и фактический путь файла лога.

#### Scenario: Обычный запуск

- **WHEN** приложение стартует с корректным `.env`
- **THEN** в начале файла есть строки с версией/ревизией, ОС, архитектурой и перечисленными путями

### Requirement: Секреты не попадают в лог

Приложение MUST NOT записывать токен Яндекс Музыки и заголовок `Authorization`. Любое значение после `OAuth ` MUST заменяться на `***` и в файле, и в окне.

#### Scenario: Токен в тексте ошибки

- **WHEN** сообщение содержит `Authorization: OAuth abcdef123`
- **THEN** в файл и в окно попадает `Authorization: OAuth ***`

### Requirement: Ротация по размеру

Когда размер `app.log` достигает 5 МиБ, приложение MUST переименовать его в `app.log.1`, заменив прежнюю резервную копию, и продолжить запись в новый `app.log`. Приложение MUST хранить не более одной резервной копии.

#### Scenario: Достижение предела

- **WHEN** очередная запись превышает предел 5 МиБ
- **THEN** текущий `app.log` становится `app.log.1`, а запись продолжается в новый `app.log`

#### Scenario: Повторная ротация

- **WHEN** новый `app.log` снова достигает предела при существующем `app.log.1`
- **THEN** прежний `app.log.1` заменяется, других резервных копий не создаётся

### Requirement: Деградация при недоступной папке

Если папка с `app.exe` недоступна для записи, приложение MUST писать лог в `%LOCALAPPDATA%\YandexMusicDownloader\app.log`. Если недоступны оба места, приложение MUST продолжать работу и писать только в окно, а при старте MUST сообщить в окне, что файловый лог недоступен.

#### Scenario: Папка только для чтения

- **WHEN** рядом с `app.exe` нельзя создать файл
- **THEN** лог пишется в `%LOCALAPPDATA%\YandexMusicDownloader\app.log`, приложение работает штатно

#### Scenario: Оба места недоступны

- **WHEN** запись невозможна и рядом с exe, и в `%LOCALAPPDATA%`
- **THEN** приложение продолжает работу, а в окне появляется предупреждение об отключённом файловом логе

### Requirement: Путь к логу виден в окне

При старте приложение MUST выводить в окно строку `[log] файл: <путь>` с фактическим путём файла лога. Если файловый лог отключён, строка MUST сообщать об этом.

#### Scenario: Лог включён

- **WHEN** приложение стартует и файл лога открыт
- **THEN** в окне есть строка `[log] файл: <путь>` с этим путём

#### Scenario: Лог отключён

- **WHEN** файл лога открыть не удалось
- **THEN** в окне есть строка о том, что файловый лог отключён

### Requirement: Потокобезопасная запись

Запись в файл MUST быть потокобезопасной: параллельные вызовы лога не должны перемешивать части разных записей.

#### Scenario: Параллельные скачивания

- **WHEN** несколько воркеров пишут в лог одновременно
- **THEN** каждая запись занимает целые строки, части разных сообщений не чередуются
