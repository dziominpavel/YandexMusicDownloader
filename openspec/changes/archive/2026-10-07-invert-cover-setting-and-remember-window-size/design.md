## Context

См. proposal.md — Why. Технический контекст, влияющий на подход:

- `config.Load` вызывается в `ui.NewApp()` до `wails.Run`, то есть сохранённый размер окна доступен до создания окна.
- В Wails v2.15 (версия в `src/go.mod`) у `options.App` **нет** поля `OnResize` — хуков на ресайз в бэкенде не существует. Есть `OnBeforeClose(ctx) bool` и `runtime.WindowGetSize/WindowIsNormal`.
- `config.Write(path, updates)` заменяет только переданные ключи и сохраняет комментарии и чужие ключи — новые ключи не ломают существующий `.env` и не теряются при сохранении настроек из окна.
- `downloader.Client.SkipCover` объявлен, но не читается ни одним кодом.
- Прод-пользователей нет: ломать формат `.env` безопасно.

## Goals / Non-Goals

**Goals:**

- Один положительный по смыслу переключатель обложки с включённым по умолчанию значением — на всех уровнях (`.env`, бэкенд, биндинг, UI, спеки).
- Окно первого запуска 864×576 и восстановление последнего обычного размера при следующих запусках.
- Тестируемая логика без живого окна: чтение/запись размера выносятся в чистые функции.

**Non-Goals:**

- Миграция старых `.env`: `SKIP_COVER` просто перестаёт читаться, алиаса не будет.
- Минимальный размер окна (`MinWidth/MinHeight`) — сейчас окно можно сжать до нерабочего, но это отдельная фича.
- Запоминание позиции окна и состояния «развёрнуто».
- Сохранение размера при каждом ресайзе (см. решение ниже) — учитывается только корректное закрытие окна.
- Правка `docs/07-architecture-proposal.md` и `docs/08-requirements.md` (F8) — исторический разбор доноров и чеклист v0.1; формальный источник истины — `openspec/specs/`.

## Decisions

**1. Полная замена ключа `SKIP_COVER` → `EMBED_COVER`, а не инверсия только в UI.**
Альтернатива — инвертировать только подписи на фронте и оставить ключ: отклонена, пользователь выбрал «сразу по-полному», прод-пользователей нет. Плата: правка `config`, `tagger`, `ui`, тестов, `.env.example`, `CHANGELOG` и двух дельта-спек. Старый ключ становится обычным «чужим» ключом: `config.Write` его аккуратно сохранит, `Load` проигнорирует.

**2. Невалидное значение `EMBED_COVER` игнорируется, флаг остаётся включённым.**
Для флага с дефолтом «вкл» разбор зеркален существующему `CONVERT_M4A`: выключают только явные `0/false/no/off`, всё прочее не влияет. Альтернатива — трактовать мусор как «выкл» (как было у `SKIP_COVER`): отклонена, инверсия смысла сделала бы опечатку в `.env` причиной исчезновения обложек.

**3. `tagger.Adapter(embedCover bool)` — параметр инвертируется, а не вызывается как `Adapter(!cfg.EmbedCover)`.**
Альтернатива — оставить `skipCover` в сигнатуре и инвертировать снаружи: отклонена, двойное отрицание переезжает в точку вызова и остаётся в коде.

**4. Мёртвое поле `downloader.Client.SkipCover` удаляется.**
Оно не читается никем (проверено поиском) — аналогично уже удалённому `FORMAT` из задачи 1.4 параллельного change. Альтернатива — оставить: отклонена, поле вводит в заблуждение относительно источника истины (источник — `tagger.Adapter`).

**5. Размер окна: чтение через `app.InitialSize()` до `wails.Run`, запись в `OnBeforeClose`.**
Значения берутся из `config.WindowWidth/WindowHeight`, при отсутствии/мусоре — константы `DefaultWindowWidth=864`, `DefaultWindowHeight=576` в пакете `ui`. В `BeforeClose`: `runtime.WindowIsNormal` → `runtime.WindowGetSize` → запись только если размер отличается от последнего сохранённого, хук всегда возвращает `false` (закрытие не отменяется).
Альтернативы:
- *Писать из фронта по `window.innerWidth`* — отклонена: это CSS-пиксели, на дисплее с масштабом 125/150% они делятся на `devicePixelRatio`, и окно сжималось бы при каждом следующем запуске.
- *Сохранять при каждом ресайзе (дебаунс)* — отклонена: хука `OnResize` в Wails v2.15 нет, пришлось бы звать бэкенд из DOM-события resize и дёргать `.env` на каждое перетаскивание.
- *Отдельный `window.json` рядом с exe* — отклонена: пользователь просил файл с настройками, а `.env` уже пишется через `config.Write`, который новые ключи не ломает.

**6. Развёрнутое окно не сохраняется.**
`runtime.WindowIsNormal(ctx) == false` → запись пропускается, остаётся прошлый обычный размер. Альтернатива — запоминать и состояние развёрнутости отдельным ключом и восстанавливать его: отклонена, не просили, а неправильно сохранённый развёрнутый размер хуже, чем его отсутствие.

**7. Логика записи размера выносится в чистую функцию** (принимает размер, флаг «обычное окно» и путь к `.env`), потому что `runtime.*` требует живого окна и в тестах недоступен. Покрытие: `InitialSize` (дефолт/заданные/мусор) и round-trip новых ключей через `config.Load`/`config.Write`.

**8. Дельта `audio-tagging` пишется как надмножество.**
Параллельный change `add-progress-statusbar-and-settings` тоже MODIFIES требование «Обложка». Моя дельта содержит и оговорку параллельного change («настраиваемым из окна настроек», «без перезапуска»), и новый формулировку флага — тогда архивация любого из change'ев даёт корректный текст, а не потерявшую половину.

## Risks / Trade-offs

- [Конфликт архивации с `add-progress-statusbar-and-settings`: две дельты MODIFIES на одно требование «Обложка» и две дельты на `desktop-app`] → перед архивацией свести формулировки вручную и прогнать `openspec validate --all`; моя дельта — надмножество (решение 8).
- [`OnBeforeClose` не срабатывает при убийстве процесса — размер не сохранится] → принято: пользователь явно выбрал сохранение при закрытии.
- [В личном `.env` останется осиротевший `SKIP_COVER`] → безвредно (читаться не будет), удалить руками; в `CHANGELOG` и `.env.example` порядок описан.
- [Сохранение размера пишет `.env` мимо `SaveSettings`] → гонка невозможна: закрытие окна и клик «Сохранить» не происходят одновременно, а `config.Write` пишет через temp-файл + rename.
- [864×576 может остаться мелким на дисплее с масштабом 150%] → проверить глазами до архивации; если мало — поднять константы и заодно поправить спеку `desktop-app` (значение зафиксировано в требовании).
- [При первом запуске `envPath` может быть неизвестен (путь к exe не резолвится)] → запись размера пропускается, окно открывается дефолтным; поведение не ухудшается.

## Migration Plan

Прод-пользователей нет, миграция не нужна. Локально: убрать из своего `.env` строку `SKIP_COVER` по желанию; новые ключи `EMBED_COVER`/`WINDOW_WIDTH`/`WINDOW_HEIGHT` появятся сами (первый — при сохранении настроек, второй — при закрытии окна). Откат — обычный `git revert`, старый формат `.env` остаётся читаемым после отката (новые ключи просто игнорируются).

## Open Questions

- Стоит ли добавить `MinWidth/MinHeight`, чтобы окно нельзя было сжать до нерабочего состояния. Не влияет на этот change: спеку, подход и набор задач не меняет, при желании — отдельным change'ем.
