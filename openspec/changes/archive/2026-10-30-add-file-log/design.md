# Design

## Context

Сейчас единственный потребитель лога — окно: `App.log` отправляет строку в Wails-событие `log` (или в `logSink` в тестах). Файлового лога нет, конфиг и `.env` лежат рядом с `app.exe`, приложение поставляется портативно одним exe. Скачивание идёт пулом воркеров, поэтому строки приходят из разных горутин.

## Goals / Non-Goals

**Goals:**

- Писать в файл ровно те строки, что видит пользователь, плюс шапку запуска.
- Не менять UX и не добавлять настроек: лог включён всегда.
- Не терять приложение и не зацикливаться, если файл недоступен.
- Не допустить утечки токена в файл.

**Non-Goals:**

- Просмотр лога внутри приложения, уровни важности, фильтрация, structured JSON.
- Сбор crash dump'ов и перехват паник Wails.
- Ротация по дате и хранение истории запусков.
- Внешние зависимости для логирования.

## Decisions

### Отдельный пакет `internal/applog`

Логгер живёт в `src/internal/applog`, а не в `ui`: его можно тестировать без Wails, а `ui` не обрастает файловыми деталями. Интерфейс минимальный: `Open(path, maxBytes) (*Logger, error)`, `(*Logger).Write(text, kind string) error`, `(*Logger).Path() string`, `(*Logger).AddSecret(s string)`.

Альтернатива — `log/slog` с кастомным handler'ом: даёт уровни и структуру, которых в UI-логе нет, и требует переписывать формат. Отклонено.

### Файл рядом с exe, fallback в `%LOCALAPPDATA%`

Основной путь — `filepath.Dir(os.Executable())/app.log`: совпадает с `.env`, `downloads/` и `library-index.json`, пользователь найдёт файл там же. Если открыть нельзя — `os.UserCacheDir()/YandexMusicDownloader/app.log` (на Windows это `%LOCALAPPDATA%`). Если и это не вышло — логгер `nil`, окно продолжает работать.

Альтернатива — всегда `%APPDATA%`: надёжнее для установленных программ, но ломает портативность и прячет файл от пользователя. Отклонено.

### Запись через тот же `logSink`

`App.log` сначала отдаёт строку в файл, затем в окно (или в `logSink` в тестах). Порядок не важен, но единая точка гарантирует, что в файл попадает всё, что видит пользователь, и ничего лишнего. `logSink` в тестах остаётся прежним — файл подключается отдельным полем `App.logFile`, поэтому существующие тесты не меняются.

### Редакция секретов на входе в логгер

`Logger.Write` заменяет `OAuth <значение>` на `OAuth ***` регулярным выражением и дополнительно вырезает точное значение токена, зарегистрированное через `AddSecret` при применении конфига. Одной регулярки мало: токен может попасть в текст ошибки без префикса `OAuth`. Редакция выполняется до записи и до отправки в окно — так скриншот окна тоже безопасен.

Альтернатива — не логировать заголовки вообще: не покрывает ошибки, где токен оказался в URL или тексте.

### Ротация: 5 МиБ, один backup, close→rename→reopen

Перед записью логгер проверяет `size + len(record) > maxBytes`; при превышении закрывает файл, переименовывает `app.log` в `app.log.1` (с заменой), открывает новый. Закрытие перед `Rename` снимает вопрос блокировки файла на Windows и не зависит от share-флагов. Размер ведётся в памяти, стартовый берётся из `os.Stat`.

Альтернатива — `lumberjack`: тянет зависимость ради одного файла и своей политикой имён. Отклонено.

### Шапка из `debug.ReadBuildInfo`

Версию берём из `runtime/debug.ReadBuildInfo()`: `Main.Version` (для локальной сборки `(devel)`) и `vcs.revision`/`vcs.time`/`vcs.modified`. Это не требует менять сборку и даёт коммит, по которому видно, какая именно сборка у пользователя. Если данных нет — пишем `unknown`.

Альтернатива — прокидывать версию через `-ldflags`: точнее, но требует правок `build-windows.ps1` и `pack-zip.ps1`; можно добавить позже, формат шапки это переживёт.

### Инициализация до `wails.Run`

`main` открывает логгер до запуска окна, чтобы ошибки инициализации Wails тоже попали в файл, и передаёт его в `ui.App`. `Startup` пишет шапку с путями (`.env`, папка загрузок, фактический путь лога) и строку `[log] файл: ...` в окно. Пути известны только `App`, поэтому шапка делится: build/OS/пути exe и лога — при открытии, конфигурационные пути — в `Startup`.

## Risks / Trade-offs

- **Антивирус или бэкап держит `app.log`** → `Rename`/`OpenFile` вернут ошибку; логгер помечает себя сломанным, приложение продолжает работу только с окном.
- **Файл растёт при долгом плейлисте** → предел 5 МиБ и один backup ограничивают максимум ~10 МиБ.
- **Токен попадёт в лог в неожиданном формате** → редакция по точному значению токена плюс regex `OAuth`, тест на оба случая.
- **Параллельные записи из пула** → мьютекс на `Write`, тест с горутинами.
- **Шапка врёт про версию локальной сборки** → явное `(devel)`/`unknown` вместо выдуманного номера; VCS-ревизия остаётся точной.

## Migration Plan

Миграции нет: файл создаётся при первом запуске новой сборки. В `.gitignore` добавляются `app.log` и `app.log.1`, в архив релиза они не попадают. Откат — удалить файл и вернуть прежнюю сборку; формат `.env` не меняется.
