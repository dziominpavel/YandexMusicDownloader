# Proposal

## Why

Сейчас приложение пишет лог только в окно: после закрытия окна или при сбое скачивания не остаётся никаких следов, и причину приходится выяснять вручную, воспроизводя загрузку отдельным кодом. Из-за этого разбор инцидента 29.10.2026 (недоступность `storage.mds.yandex.net`) занял время, хотя точная ошибка была известна приложению.

## What Changes

- Все строки, попадающие в окно лога, дополнительно пишутся в файл `app.log` рядом с `app.exe`.
- В начале файла — шапка запуска: версия приложения, ОС/архитектура, пути к `.env`, папке загрузок и самому логу. Токен и заголовок `Authorization` в лог не попадают.
- Файл ограничен по размеру: при достижении 5 МБ он переименовывается в `app.log.1` (одна резервная копия), запись продолжается в новый `app.log`.
- Если папка с exe недоступна для записи, приложение не падает и не теряет лог: файл уходит в `%LOCALAPPDATA%\YandexMusicDownloader\app.log`, а в окно выводится строка с фактическим путём.
- В окно при старте выводится строка `[log] файл: <путь>`, чтобы пользователь мог найти лог без инструкции.
- Формат строки: `2026-10-30T12:34:56+03:00 [error] текст`.

## Capabilities

### New Capabilities

- `file-log`: диагностический файловый лог приложения — расположение, формат, ротация, защита секретов и деградация при недоступной папке.

### Modified Capabilities

Нет: поведение окна, настроек и скачивания не меняется, добавляется только дублирование уже существующих строк в файл.

## Impact

- Новый пакет `src/internal/applog` (открытие файла, запись, ротация, редакция секретов) и его тесты.
- `src/internal/ui/app.go`: `App.log` дополнительно пишет в файл; `Startup` пишет шапку и путь к логу.
- `src/cmd/app/main.go`: инициализация лога до запуска окна, чтобы падения Wails тоже попадали в файл.
- `.gitignore`: `app.log`, `app.log.1`.
- Дистрибуция не меняется: лог создаётся при первом запуске, в архив не входит.
