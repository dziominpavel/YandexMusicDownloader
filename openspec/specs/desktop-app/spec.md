## Purpose

Окно Windows-приложения и поставка одним exe-файлом: пользователь без кода и консоли вставляет ссылку и получает музыку.

## Requirements

### Requirement: Окно с полем, кнопкой и логом

Приложение MUST открываться как обычное Windows-окно с полем для ссылки, кнопкой «Скачать», кнопкой «Настройки», агрегированным статусбаром прогресса (см. capability `track-download`) и строковым логом. Все тексты интерфейса — на русском.

#### Scenario: Скачивание из окна

- **WHEN** пользователь вставляет ссылку на трек в поле и нажимает «Скачать»
- **THEN** в логе появляется `[downloading] Artist — Title`, а по завершении — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Ошибка видна в окне

- **WHEN** скачивание завершается ошибкой (нет сети, неверная ссылка, недоступный трек)
- **THEN** в логе появляется `[error] Artist — Title` с краткой причиной на русском, окно остаётся открытым

#### Scenario: Настройки открыты из окна

- **WHEN** пользователь нажимает «Настройки»
- **THEN** открывается окно настроек (см. capability `app-settings`), главный экран при этом остаётся позади

### Requirement: Один exe без консоли и зависимостей

Приложение MUST поставляться одним `app.exe`, который запускается двойным кликом без установки рантайма и без чёрного окна консоли. Токен приложение MUST читать из `.env` рядом с exe, и этот же файл MUST редактироваться окном настроек (инструкция по ручному созданию `.env` — отдельно, не в этом change).

#### Scenario: Запуск у друга

- **WHEN** друг кладёт `app.exe` и настроенный `.env` в одну папку и запускает exe
- **THEN** открывается окно приложения, готовое к вставке ссылки

#### Scenario: Токен введён через настройки

- **WHEN** у пользователя нет `.env`, он ввёл токен в окне настроек и сохранил
- **THEN** рядом с exe создаётся/дополняется `.env` с токеном, приложение готово к скачиванию без ручной правки файла

### Requirement: Дистрибутивный архив

Архив релиза MUST содержать единственный корневой каталог `YandexMusicDownloader`, внутри которого лежат `app.exe` и `ffmpeg.exe`. `app.exe` и `ffmpeg.exe` MUST NOT находиться в корне архива. Сборка архива MUST завершаться ошибкой, если структура не соответствует.

#### Scenario: Скачал и распаковал

- **WHEN** пользователь распаковывает архив релиза
- **THEN** он видит одну папку `YandexMusicDownloader` с `app.exe` и `ffmpeg.exe` внутри, без файлов в корне архива

#### Scenario: Запуск из папки

- **WHEN** пользователь запускает `app.exe` из распакованной папки, сохраняет настройки и скачивает трек
- **THEN** `.env` и `downloads/` появляются рядом с exe, внутри той же папки; `library-index.json` при включённой проверке дублей — там же

#### Scenario: Структура архива нарушена

- **WHEN** сборка архива обнаруживает файлы в корне или отсутствие каталога `YandexMusicDownloader`
- **THEN** сборка завершается с ненулевым кодом и понятным сообщением, а некорректный архив не публикуется

### Requirement: Запоминание размера окна

Приложение MUST открываться с размером 950×634, если сохранённый размер отсутствует. Последний обычный (не развёрнутый) размер окна MUST сохраняться в `.env` рядом с exe при закрытии окна (ключи `WINDOW_WIDTH`, `WINDOW_HEIGHT`) и MUST восстанавливаться при следующем запуске. При закрытии развёрнутого окна MUST сохраняться предыдущий обычный размер, а не размер развёрнутого окна.

#### Scenario: Первый запуск

- **WHEN** приложение запущено впервые, в `.env` нет `WINDOW_WIDTH` и `WINDOW_HEIGHT`
- **THEN** окно открывается с размером 950×634

#### Scenario: Размер запомнился

- **WHEN** пользователь изменил размер окна, закрыл его и запустил приложение снова
- **THEN** окно открывается с сохранённым размером

#### Scenario: Развёрнутое окно не сохраняется

- **WHEN** пользователь развернул окно на весь экран и закрыл его
- **THEN** при следующем запуске окно открывается с предыдущим обычным размером, а не развёрнутым

#### Scenario: Ручная правка размера

- **WHEN** пользователь вручную прописал `WINDOW_WIDTH=1000` и `WINDOW_HEIGHT=700` в `.env`
- **THEN** окно открывается с размером 1000×700

### Requirement: Кнопка остановки активной загрузки

Пока идёт job'а, кнопка «Скачать» MUST превращаться в кнопку «■ Остановить» (красную), а не блокироваться: остановка доступна в один клик и только для активной загрузки. По нажатию кнопка MUST перейти в состояние «Останавливаю…» и не позволять отправить команду остановки повторно, пока бэкенд не завершит job'у. После остановки или завершения кнопка MUST вернуться в «Скачать», кнопка настроек — снова стать доступной. Остановка MUST приходить в тот же процесс, что и скачивание (биндинг `App.Stop`) и MUST прерывать активную job'у без перезапуска приложения.

#### Scenario: Остановка плейлиста

- **WHEN** качается плейлист, пользователь нажимает «■ Остановить»
- **THEN** активные запросы обрываются, не начатые треки не стартуют, в логе появляется итог `[stopped] прервано: ...`, статусбар замораживается на фактическом проценте (не 100%)

#### Scenario: Остановка одиночного трека

- **WHEN** качается один трек, пользователь нажимает «■ Остановить»
- **THEN** трек получает статус `[stopped]` (не `[error]`), частично скачанный временный файл удаляется, кнопка возвращается в «Скачать»

#### Scenario: Следующая загрузка после остановки

- **WHEN** после остановки пользователь снова нажимает «Скачать»
- **THEN** предыдущая остановка сброшена, новая job'а идёт в обычном режиме
