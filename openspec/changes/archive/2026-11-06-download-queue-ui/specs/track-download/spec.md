# Spec Delta

## MODIFIED Requirements

### Requirement: Скачивание трека по ссылке

Приложение MUST принимать ссылку вида `music.yandex.ru/album/{albumId}/track/{trackId}`, ссылку вида `music.yandex.(ru|com|kz|by|uz)/album/{albumId}` (без trackId), ссылку вида `music.yandex.(ru|com|kz|by|uz)/playlists/{uuid}` (включая префиксы вида `lk.<uuid>`, `ps.<uuid>` и query-хвосты), а также несколько ссылок в одном вводе (разделённые переносом строки, пробелом или запятой). Ссылки MUST ставиться в очередь задач (см. capability `download-queue`), а аудио — сохраняться в `OUTPUT_DIR` (по умолчанию `./downloads`). В логе статусы MUST использовать технические токены, а в строке задачи MUST отображаться человекочитаемый статус, соответствующий токену.

#### Scenario: Вставил ссылку — получил файл

- **WHEN** пользователь вставляет ссылку на трек и нажимает «Скачать»
- **THEN** в журнале появляется `[downloading] Artist — Title`, а после завершения — `[done] Artist — Title (FLAC|MP3)`

#### Scenario: Файл уже есть

- **WHEN** целевой файл уже существует в папке назначения
- **THEN** скачивание пропускается и в журнале появляется `[skip] Artist — Title (already exists)`

#### Scenario: Вставил ссылку на плейлист — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.by/playlists/{uuid}` и нажимает «Скачать»
- **THEN** появляется запись `[playlist] Название (N треков)` и ровно по одной строке задачи на каждый уникальный трек (в порядке плейлиста, со статусом «В очереди», которому в логе соответствует `[queued]`), а в конце — `[finished] X ok, Y skip, Z error`

#### Scenario: Вставил ссылку на альбом — получил файлы

- **WHEN** пользователь вставляет ссылку вида `music.yandex.ru/album/{albumId}` и нажимает «Скачать»
- **THEN** приложение резолвит альбом в список треков и ставит их задачами источника так же, как плейлист: запись `[album] Название (N треков)`, по одной строке на каждый трек, общий прогресс очереди, итоговая строка `[finished] X ok, Y skip, Z error`

#### Scenario: Одна строка на трек

- **WHEN** трек в очереди качается и завершается
- **THEN** его строка обновляется на месте («В очереди» -> «Скачивается» -> «Готово - FLAC|MP3» с цветом), новые строки на каждое событие НЕ добавляются; строка пропуска показывает «Пропущено - уже есть|дубль|недоступно», строка ошибки — «Ошибка» с причиной; в логе этим состояниям соответствуют `[queued]`, `[downloading]`, `[done]`, `[skip]` и `[error]`

#### Scenario: Плейлист с query-хвостом и префиксом

- **WHEN** ссылка имеет вид `music.yandex.ru/playlists/lk.<uuid>?utm_source=web`
- **THEN** приложение принимает ее как плейлист и резолвит тот же набор треков, что и без префикса и хвоста

#### Scenario: Несколько ссылок разом

- **WHEN** пользователь вставляет в поле ввода несколько ссылок (разделённые переносом строки, пробелом или запятой), нажимает «Скачать»
- **THEN** каждая ссылка ставится отдельным источником в очередь, применяя соответствующий пайплайн (альбом/плейлист/трек), а их треки качаются общим пулом. Если одна из ссылок некорректна — она пропускается с `[error]`, остальные ставятся и обрабатываются дальше.

### Requirement: Пакетное скачивание плейлиста

Приложение MUST скачивать треки плейлиста и альбома пулом параллельных воркеров с настраиваемым числом (`PLAYLIST_WORKERS` в `.env`: целое 1..10, по умолчанию 3), общим для всей очереди (см. capability `download-queue`), при этом каждый трек MUST проходить стандартный пайплайн (FLAC first с MP3-fallback, обязательные теги, потоковая запись, атомарная публикация `temp → rename`). Ошибка или недоступность одного трека MUST NOT останавливать остальные. Повтор одного и того же ID MUST скачиваться один раз, повторные вхождения пропускаются как уже обработанные.

#### Scenario: Пачка из нескольких треков

- **WHEN** плейлист или альбом содержит 5 уникальных доступных треков
- **THEN** все 5 файлов появляются в `downloads/` с тегами, 5 строк задач переходят в «Готово - FLAC|MP3», а финал — `[finished] 5 ok, 0 skip, 0 error`

#### Scenario: Недоступный трек пропускается

- **WHEN** трек плейлиста или альбома недоступен (`available=false`, нет прав, 403/404)
- **THEN** строка задачи показывает «Пропущено - недоступно» (`[skip] (unavailable)` в логе), остальные треки качаются дальше, счетчик `skip` в финале увеличивается

#### Scenario: Дубль качается один раз

- **WHEN** один и тот же ID встречается в плейлисте или альбоме дважды
- **THEN** файл скачивается один раз, строка задачи показывает «Пропущено - дубль» (`[skip] (duplicate)` в логе), повторной записи файла нет

#### Scenario: Ошибка одного не роняет пачку

- **WHEN** один трек завершается ошибкой сети или тегирования
- **THEN** строка задачи показывает «Ошибка» с причиной (`[error]` в логе), остальные треки продолжают качаться, финал учитывает ошибку в счетчике `error`

#### Scenario: Число воркеров настраивается

- **WHEN** в `.env` задано `PLAYLIST_WORKERS=10`
- **THEN** до 10 задач качаются параллельно, в том числе треки из разных источников очереди

#### Scenario: Мусор в настройке воркеров

- **WHEN** `PLAYLIST_WORKERS` отсутствует, не число или вне диапазона 1..10
- **THEN** приложение использует значение по умолчанию 3 и работает как обычно

### Requirement: Прогресс скачивания трека

Приложение MUST показывать живой прогресс по каждой качающейся задаче очереди (байты и проценты при известном размере, только байты при неизвестном), обновляя строку задачи на месте, а не добавляя новые строки. Обновления MUST быть троттлированы (не чаще ~200 мс или +1% на задачу), чтобы не затапливать UI. Статусы задач MUST обновляться в их строках; в обычный журнал попадают только запись источника и итоговая строка `[finished]`.

#### Scenario: Виден процент по треку

- **WHEN** качаются 3 задачи параллельно с известным размером
- **THEN** в окне видны 3 обновляющиеся строки вида `Artist — Title 42% 18/43 МБ`, каждая обновляется независимо

#### Scenario: Неизвестный размер

- **WHEN** сервер не отдал размер файла
- **THEN** строка прогресса показывает только скачанные байты вида `Artist — Title 12 МБ`, без процентов, и трек завершается обычным `[done]`

### Requirement: Проверка на возможный дубль перед скачиванием

Если задан `LIBRARY_DIR` (см. capability `library-index`), приложение MUST перед стартом каждой задачи искать совпадения в индексе и при схожести выше порога переводить задачу в состояние «возможен дубль». Строка задачи MUST показывать процент, название трека, имя и полный путь найденного файла (перенос по символам, копирование), а для файла другого формата — предупреждение о двух форматах. «Скачать всё равно» и «Пропустить» MUST применяться к этой задаче; отказ пропускает её с записью в журнал.

#### Scenario: Дубля нет

- **WHEN** в индексе нет файлов со схожестью выше порога
- **THEN** скачивание начинается без вопроса, как обычно

#### Scenario: Найден похожий файл — подтверждение

- **WHEN** найден кандидат со схожестью выше порога (например 93%)
- **THEN** строка задачи переходит в «возможен дубль» и показывает процент совпадения, название скачиваемого трека, имя и полный путь найденного файла; по «Скачать всё равно» задача скачивается, по «Пропустить» — не скачивается, а в журнале появляется строка о пропуске

#### Scenario: Длинный путь виден целиком

- **WHEN** полный путь найденного файла не помещается в одну строку
- **THEN** путь переносится по символам и отображается целиком без обрезки, имя файла показано отдельно, а текст пути можно выделить и скопировать

#### Scenario: Плейлист — подтверждение на каждый трек

- **WHEN** в плейлисте несколько треков совпали с файлами коллекции
- **THEN** по каждой такой задаче запрашивается отдельное решение; трек без совпадений качается без вопросов, а отказ по одной задаче MUST NOT останавливать остальные

#### Scenario: Уже есть в другом формате

- **WHEN** в коллекции уже лежит такой же трек в MP3, а сейчас качается FLAC (или наоборот)
- **THEN** строка задачи предупреждает о возможном дубле с явным указанием, что найденный файл имеет другой формат

#### Scenario: Проверка выключена

- **WHEN** `LIBRARY_DIR` в `.env` не задан
- **THEN** вопросов о дублях нет, поведение полностью соответствует прежнему

### Requirement: UX улучшения без настроек

Приложение MUST поддерживать drag & drop ссылок на окно, кнопку «Открыть папку загрузок» и предпросмотр ссылки (обложка, название, артист, количество треков для альбома/плейлиста) в виде компактной подсказки под полем ввода. Предпросмотр MUST NOT блокировать постановку в очередь; при ошибке он MUST скрываться без ошибки. Все эти функции MUST быть включены всегда, без опций в окне настроек. Приложение MUST NOT хранить историю ссылок в `.env`, localStorage или файлах; журнал текущей сессии — события загрузок, а не история ссылок.

#### Scenario: Drag & drop

- **WHEN** пользователь перетаскивает ссылку Яндекс.Музыки на окно
- **THEN** ссылка подставляется в поле ввода и можно сразу поставить её в очередь

#### Scenario: Открыть папку загрузок

- **WHEN** пользователь нажимает «Открыть папку загрузок»
- **THEN** системный проводник открывается на папке `OUTPUT_DIR`

#### Scenario: Предпросмотр ссылки

- **WHEN** в поле ввода вставлена валидная ссылка на трек/альбом/плейлист
- **THEN** показывается компактная подсказка (обложка, название, артист/кол-во треков) под полем. Постановка в очередь работает независимо от подсказки; если превью не загрузилось — подсказка скрывается

#### Scenario: История ссылок

- **WHEN** пользователь вставил ссылку и поставил её в очередь
- **THEN** выпадающий список истории не появляется, ссылка не сохраняется в localStorage, а журнал сессии не превращается в историю ссылок

## REMOVED Requirements

### Requirement: Агрегированный статусбар прогресса

**Reason**: Агрегированный прогресс переехал в очередь задач: процент, счётчики и байты теперь считаются по всем задачам всех источников, а не по одной job'е.

**Migration**: Сводка и полоса прогресса описаны в capability `download-queue`; состояния экрана — в capability `desktop-app`.
